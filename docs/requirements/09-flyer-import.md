# 09. チラシ取り込みの分類（D-100・D-101）

優先度：**必須**

チラシから読み取った商品を、アプリ（Biz）が **3つの分類**（使えない / 再入力 / 取り込める）に分け、職員は「再入力」を直してから「取り込みを終える」を1回押す。2026-11-07 に、取り込みの仕様を大きく変えた（[07 の D-100](07-open-questions.md)）。同じ日に、職員に頼むことを「再入力」と「避ける品目を含む商品を外す（使えない）」だけに絞り、チラシとの最終の見比べを献立の確定のときに移した（[07 の D-101](07-open-questions.md)）。

- この文書は、[02 の 3](02-functional.md#3-チラシ取り込みfr-flyer)（FR-FLYER）・[03 の 2.5](03-allergen-safety.md#25-チラシの表記の略記)・[05 の SC-09 手順1](05-screens.md#手順1チラシ取り込み) のうち、**照合・分類・確定**の部分を置き換える。置き換えるもの・残すものは 8 にまとめた
- この文書と 02・03・05 が食い違うときは、この文書を正とする。ただし 03 の安全要件（SR）の考え方（迷ったら確認する側に倒す・Claude の出力でアレルゲンの判定を緩めない）は変えない

## 1. 変えたことの要点

### 1.1 D-101 で変えたこと（D-100 からの差分）

| D-100 | D-101 |
| --- | --- |
| 分類は **使えない / 再入力 / 要確認 / 使える** の4つ（と確定済み・外した掲載品） | 分類は **使えない / 再入力 / 取り込める** の3つ（と確定済み・外した掲載品）。「要確認」と「使える」の区別をなくし、新しい商品も既存の商品も「取り込める」にする（新しい商品かどうかは行の印で示すだけ） |
| 再入力の理由は11個（税込と税抜の不整合・内容量や注文番号が読めない・入数の候補の指摘・読み取りの検証の指摘・内容量や入数がマスタと違う・二重に読んだ値の食い違いなどを含む） | 再入力は **5つ**（商品名・メーカー・税込価格が読めない、品目の分からない語、表記なしなのに一致した商品の記録で特定原材料を「含む」）。ほかは「**注意**」として行に出すだけにし、アプリが値を決めて自動で進める（3.8） |
| 再入力は「直す」か「このままでよい」 | 「**このままでよい」はなくす**。直すと分類し直す |
| 「使える商品をまとめて確定」「新しい商品をまとめて登録」と1件ずつの確定。まとめに入れない例外（表記なしの見比べ前・手入力・入数を入れ直した・検証ができなかった・直している途中・分類か入数の候補がない） | 「**取り込みを終える**」1回の操作で、取り込めるの商品の新規登録と既存の商品の上書きをまとめて行う。まとめから外す例外（旧 5.2）・1件ずつの確定・まとめて確定とまとめて登録のダイアログ（D-98 を含む）はなくす（5） |
| 表記なしの商品は、表の上のまとめからチラシと見比べて印を付ける（FR-FLYER-04a・D-97） | **表記なしの見比べはなくす**。表記なしの商品は「参考（表記なし）」で記録し（今までどおり）、献立の確定のときに、今週のチラシの表記の原文（「表記なし」）を見てもらう（5.4） |
| 内容量・入数がマスタと違えば再入力にし、職員が確かめてから上書き | 注意を出して、チラシの値で自動で上書きする（過去の週は上書きせず、空のときだけ埋める）。「内容量が変わりました。届いたらパッケージの原材料も見てください」を添える（3.8） |
| 献立の確定の確認のチェック（SR-04）は、商品名と警告の理由・次にすること | 掲載品の写し（`menus.listed_products`）に**今週のチラシの表記の原文**を持ち、確認のチェックに出して「チラシの表記と見比べて、パッケージが届いたら原材料を確かめてください」と添える（5.4） |

**変えないもの**：照合（名前＋メーカーの完全一致。2）、略記の補正（4）、避ける品目の判定（3.4）、確認済みとの食い違いで「参考」の記録を自動で足すこと（3.5。保存は取り込みを終えるとき）、外した掲載品（3.7）、手入力（D-73）、読み取りの検証そのもの（FR-FLYER-03g）、タグ・おやつの分類の候補、データの移行（9）。分類はサーバーが決め、取り込みを終える API でもサーバーが分類を求め直し、**使えない・再入力は決して確定しない**。

**安全の考え方（D-101 で緩めないこと）**

- 「使えない」の条件（避ける品目・使わない・入数が分からない）は変えない。注意にしたものは、どれもアレルゲンの判定を変えない（読んだ品目を消さない・「含まない」にしない）
- チラシから取り込んだ商品のアレルゲンの記録は、今までどおり「参考」（表記なしは「参考（表記なし）」）で、どの品目も「含まない」にしない。新しい商品はいつも 🟡 要確認 になり、献立の確定で商品ごとの確認のチェック（SR-04）が要る
- 取り込みの画面でのチラシとの見比べ（表記なし・読み取りの検証の指摘）は、献立の確定の確認のチェックで、今週のチラシの表記の原文を見せて行ってもらう（5.4）。パッケージが届いたら原材料で確かめる（今までどおり）
- 二重に読んだ商品のアレルゲンの品目は和集合のまま（確認する側）

## 2. 商品の照合（名前＋メーカーの完全一致）

| ID | 要件 |
| --- | --- |
| FR-IMPORT-01 | 読み取った商品と商品マスタの商品は、**正規化した商品名と正規化したメーカーの両方が一致したときだけ**同じ商品とする。商品名の正規化は今の照合と同じ関数（NFKC → カタカナをひらがなに → 「CO・OP」「コープ」の除去 → 記号・空白の除去）。メーカーは「コープ」を除かない正規化（NFKC → カタカナをひらがなに → 記号・空白の除去。今の照合のメーカーの比べ方と同じ）にする（メーカーが「コープ」だけの商品のメーカーが空にならないように） |
| FR-IMPORT-02 | 内容量・税込価格・注文番号は照合に使わない（内容量が変わっても同じ商品。内容量の変化は 3.8 の「注意」で扱う。D-101） |
| FR-IMPORT-03 | チラシには**メーカーが必ず載っている**前提とする。メーカーが読めなかった（空の）商品は照合せず、「再入力」にする（メーカーを入れたら照合する）。商品マスタでメーカーが空の商品は、どのチラシの商品とも一致しない |
| FR-IMPORT-04 | 一致する商品がマスタに2件以上あるとき（内容量違いを別の商品として登録していた名残など）は、**最後にチラシに載った週**（`listed_week_start`）がいちばん新しい商品を使う。載った週が同じ・どちらも空のときは、更新日時が新しい商品、それも同じなら ID の順で決める（商品に登録日時の列がないため）。どれを使ったかは一覧に示す |
| FR-IMPORT-05 | 似ている商品の候補（Dice 係数）・Claude（Haiku）による照合の判定・職員が既存の商品を検索して紐づける操作は作らない。一致しない商品は（ほかの条件に当たらなければ）「取り込める」の新しい商品になり、取り込みを終えるときに新しい商品として登録する（D-101） |
| FR-IMPORT-06 | 正規化した名前＋メーカーが同じ商品を、1回の取り込みで2回以上読んだとき（半分ずつ撮った写真の重なりなど）は、アプリが自動で1件にまとめる。アレルゲン表記の品目・説明文で当たった探す言葉・品目の分からない語は、両方を合わせる（和集合。確認する側に倒す）。税込価格・税抜価格・内容量・注文番号・入数の候補のどれかが食い違うときは、**先に読んだ値を使い**、食い違った値を両方「注意」に示す（再入力にしない。D-101。3.8） |

- 照合は商品名と内容量の正規化をアプリ（Biz）で行い、Claude は呼ばない。照合の結果は xUnit で確かめる
- 同じ名前・メーカーで大きさ違いの商品が同じチラシに別々に載ったときも、1件にまとめる（値は先に読んだ方を使い、食い違いを注意に出す。注文番号が食い違ったときは、注意の文で大きさ違いの可能性を示す）。商品は名前＋メーカーで1つなので、今週の商品に入れられるのはどちらか1つ。後に読んだ方を使いたいときは、職員が行の詳細欄で値を直せる（直さなくても取り込める）。注文番号が違ってもまとめない扱いにはしない（分けても同じ商品に一致し、後の行が前の行を上書きするため）。両方を別の商品として扱いたいときは、商品名に大きさを含めて（例：「○○ 大袋」）手入力する。新しい商品になり、「参考」の記録から始まる（アレルゲン確認は引き継がない）
- 照合のたびに、マスタの商品名・メーカーから正規化し直して比べる（数百件なので全件でよい。正規化の関数を直しても保存値とずれない）。`normalized_maker` の列は足さない
- 読み取りの時点でまとめなかった行（手入力の行・商品名かメーカーを直してほかの行と同じ名前＋メーカーになった行）も、取り込みを終えるとき（5.1）に同じ鍵で**1件の商品にまとめる**（同じ商品を2件登録しない。2件あると、パッケージで確かめた記録が片方にしか付かず、次の週の照合で記録のない方が選ばれうるため）。先の行の商品を後の行も使い、商品の値（価格・内容量・入数など）は先の行の値のまま、チラシの品目は後の行の分も「参考」の記録で足す（和集合）。写しの表記の原文は、違えば「／」でつなぐ

## 3. 分類

### 3.1 3つの分類（D-101）

| 分類 | 意味 | 当てはまる条件 | 職員がすること |
| --- | --- | --- | --- |
| 🔴 **使えない**（赤） | 今週の商品（献立の候補）に入れない | ・入数が特定できない（3.3）<br>・避ける品目が入っている（3.4。チラシの表記・説明文の探す言葉・商品名の探す言葉・一致した商品の記録）<br>・一致した商品を商品一覧で「使わない」（FR-PROD-09）にしている | 何もしなくてよい（取り込みを終えても今週の商品に入らない）。表記の読み違いのときは直せる（3.6）。入数が分からない商品は入数を入れれば分類し直す |
| 🟠 **再入力**（橙） | 読み取りに足りないところがあり、職員が直すまで確定できない | ・商品名が読めない<br>・メーカーが読めない<br>・税込価格が読めない<br>・アレルゲン表記に、品目にも略記にも当たらない語がある（品目を選ぶか「対応する品目なし」を選ぶ）<br>・表記なしと読んだのに、一致した商品の有効な記録では特定原材料を「含む」（読み落としの疑い。D-97 から引き継ぐ） | 理由の欄を直す。直すと分類し直す（5.3）。「このままでよい」はない |
| 🟢 **取り込める**（緑） | 上のどれにも当たらない。取り込みを終えると今週の商品に入る | 使えない・再入力のどれにも当たらない（新しい商品も、商品マスタに一致する商品も） | 何もしなくてよい。「取り込みを終える」で、新しい商品は登録し、既存の商品は上書きする（5.1）。行に「注意」（3.8）が出ていても、そのまま取り込める |

- 新しい商品かどうかは、取り込めるの行に「新しい商品」の印を付けるか、一致した商品の名前を出すかで示すだけにする（分類は分けない）
- 新しい商品で、おやつの分類の候補がない商品（読み取りが分類を返さなかった。まれ）は、商品の登録に要るため「再入力」（おやつの分類を選ぶ）にする（入数の候補がない商品は 3.3 で「使えない」になる）
- 取り込みの分類の🟢「取り込める」は、「職員が商品ごとに確かめなくても今週の商品に入れてよい」という意味で、**アレルゲンの3つの表示（[03 の 6](03-allergen-safety.md#6-画面での表示)）とは別のもの**。新しい商品（記録は「参考」）や、一致した商品の記録が「参考」「要再確認」の商品も「取り込める」になり、献立では今までどおり 🟡 要確認 として扱う（確定のときの商品ごとの確認も今までどおり。SR-04。5.4 でチラシの表記の原文を足す）
- 分類の名前と色は、献立や商品一覧のアレルゲンの表示と混ざらないよう、取り込みの画面の中だけで使う。画面では「取り込みの分類」と見出しを付け、アレルゲンの表示のアイコンとは別の形（チップ）で出す
- 分類はサーバー（Biz）が決めて API で返し、画面は表示だけにする。取り込みを終える API でもサーバーが分類を求め直し、使えない・再入力になった商品は確定しない

### 3.2 分類の順番

複数の条件に当てはまるときは、**使えない ＞ 再入力 ＞ 取り込める** の順で先のものにする。理由は当てはまったものをすべて並べる（例：「税込価格が読めません／卵を含みます」→ 使えない）。注意（3.8）は分類を変えず、どの分類の行にも出す。

```
取り込みの分類(読み取った商品, 商品マスタ, 避ける品目, 今日):
    一致 = 正規化した商品名とメーカーが同じマスタの商品（2件以上なら FR-IMPORT-04）。
           商品名かメーカーが空なら「なし」
    チラシの品目 = アレルゲン表記の品目（略記の補正後。4）
                 ∪ 説明文で避ける品目の「探す言葉」が当たった品目
    入数 = 読み取りの入数の候補（1以上）、なければ 一致.入数

    使えない の理由:
        入数がない                                               → 入数が分からない
        避ける品目 ∩ チラシの品目 ≠ 空                            → ○○を含みます（チラシの表記・説明文）
        正規化した商品名に、避ける品目の「探す言葉」がある        → 商品名に「○○」があります
        一致があり、一致の判定（03 の 5）が 含む / 含む可能性あり   → 一致の判定の理由（○○を含みます など）
        一致があり、一致.使わない                                 → 「使わない」にした商品です
    使えない の理由があれば → 使えない

    再入力 の理由:
        商品名が空                                               → 商品名が読めませんでした
        メーカーが空                                             → メーカーが読めませんでした
        税込価格がない                                           → 税込価格が読めませんでした
        品目の分からない語があり、まだ品目を選んでいない          → 「○○」の品目を選んでください
        表記なし かつ 一致の有効な記録で特定原材料を「含む」        → 表記なしと読みましたが、○○を含む商品です
        一致がなく、おやつの分類の候補がない                     → おやつの分類を選んでください
    再入力 の理由があれば → 再入力

    それ以外 → 取り込める（一致がなければ「新しい商品」の印）

    注意（分類とは別に集める。3.8）
```

- 一致した商品の判定は、03 の 5 の判定（有効な記録の「含む」・商品名と原材料の全文の探す言葉）を**そのまま使う**。判定が「不明（記録がない）」のときは、今回のチラシの品目で「参考」の記録を足すもの（03 の 3 の表の「記録がない → 追加する」）とみなして分類する（チラシの品目に避ける品目がなければ「取り込める」。献立では 🟡）
- 「使えない」の理由のうち、入数が分からないこと以外（避ける品目・使わない）は、職員の操作で外せない（SR-10。避ける品目は 3.6 で表記を直したときだけ変わる）
- 避ける品目が1つも設定されていないときは、避ける品目による「使えない」は起きない（03 の 6.3 の「避ける品目が設定されていません」は今までどおり出す）

### 3.3 入数

| ID | 要件 |
| --- | --- |
| FR-IMPORT-10 | おやつは個包装のお菓子だけを出すため、**入数（1パックで何人分か）が特定できない商品は「使えない」**にする。特定できないとは、Claude が内容量の表記から入数の候補を出せず（null か0）、一致した商品にも入数がないこと |
| FR-IMPORT-11 | 「使えない（入数が分からない）」の商品には、行に入数の欄を置く。職員が入数（1以上の整数）を入れると、読み取った内容（アレルゲン表記・説明文を含む。手入力にはしない）のまま分類し直す。ほかの条件に当たらなければ「取り込める」になり、取り込みを終えるときにほかの商品と一緒に取り込む（D-101 で、まとめに入れない扱いをやめた） |
| FR-IMPORT-12 | 一致した商品があり、チラシの内容量（表記をそろえたもの）または入数の候補がマスタと違うときは、再入力にせず「注意」を出す（D-101。3.8）。取り込みを終えたら、マスタの内容量・入数をチラシの値（職員が直していればその値）で上書きする。ただし、献立の週がその商品の最後に載った週より前のとき（過去の週の取り込み。FR-FLYER-07 と同じ条件）は、マスタの内容量・入数を上書きしない（古い値に戻さないため）。マスタの内容量か入数が空のときだけ埋める。注意は過去の週でも出す |

- 内容量が変わっても、名前＋メーカーが同じなら同じ商品として扱い、**アレルゲン確認を引き継ぐ**（D-100 で SR-05 を見直した）。内容量の変わり目でリニューアル（原材料の変更）があることもあるため、FR-IMPORT-12 の注意に「内容量が変わりました。届いたらパッケージの原材料も見てください」と添える（判定は変えない）
- 入数が変わると1人あたりの金額が変わるため、注意にはマスタの値とチラシの値を並べて出す（例：「マスタは12個、チラシは10個です」）

### 3.4 避ける品目が入っているかの判定

次の**どれか1つでも**当たれば「使えない」にする。

1. **チラシのアレルゲン表記**：表記の品目（4 の略記の補正をしたあと）に避ける品目がある
2. **チラシの説明文**：説明文に、避ける品目の「探す言葉」がある（今の「チラシの品目」と同じ。説明文は保存しない）
3. **商品名**：正規化した商品名に、避ける品目の「探す言葉」がある（SR-14）
4. **商品マスタの記録**：一致した商品の判定（03 の 5）が「含む」か「含む可能性あり」（有効な記録の「含む」と、原材料の全文の探す言葉）

- 1・2 は今回のチラシだけで決まるので、マスタに一致がない（新しい）商品にも効く
- 一致した商品が「確認済み」でも、1・2 に当たれば「使えない」にする（チラシが新しい情報かもしれないため。SR-20 の扱いは 3.5）
- 判定はステータスより先に「含む」を見る（03 の 5 と同じ）

### 3.5 確認済みの商品とチラシの表記の食い違い（SR-20 の見直し）

一致した商品が「確認済み」で、チラシの品目に、有効な記録で「含む」になっていない品目があるとき：

| 増えた品目 | 分類 | 記録 |
| --- | --- | --- |
| 避ける品目 | 🔴 使えない | 「参考」の記録（チラシの品目を「含む」）を**自動で**足す |
| 避ける品目でない | 🟢 取り込める（ほかの条件に当たらなければ） | 「参考」の記録（チラシの品目を「含む」）を**自動で**足す。職員に「確認し直す / チラシの誤り」を選ばせることはやめる |

- 足した記録で、商品一覧・ほかの週の献立でも 🔴（避ける品目）か 🟡（参考）になる。パッケージで確認し直せば（新しい「確認済み」の記録）戻る（03 の 3 の「有効な記録」）
- 記録を足すのは、**「取り込みを終える」を押したとき**に、食い違いのある商品の分をまとめて保存する（分類が使えない・再入力・取り込めるのどれでも。D-101）。読み取りが終わった時点では保存しない（職員が表記を直す前の読み違いを、記録に残さないため）。取り込みを終えたあとに読み直した・直した商品は、次に取り込みを終えるときに保存する（同じ食い違いの記録を二重には足さない）
- 取り込みの一覧では、食い違いのある商品に「チラシの表記が、パッケージでの確認と食い違っています（○○）」と示し、取り込みを終えたら記録を足したことを知らせる
- 外した掲載品（職員が外したもの・Claude が食品以外としたもの）も、一致した商品があり食い違いがあれば、同じく取り込みを終えるときに記録を足す。外した理由は問わない（今週使わない商品でも、ほかの週の写しや献立に残りうるため。確認する側に倒す）。外した掲載品の一覧にも食い違いを示す。読み違いなら「戻す」で表記を直してから外す（2026-11-07 決定）
- 03 の 3 の「チラシを取り込んだときに参考の記録を追加するか」の表（記録がない → 追加 / 確認済みがある → 追加しない（食い違いはこの 3.5）/ 参考だけ → 品目が増えたときだけ追加）は変えない

### 3.6 使えない商品の表記を直す

- 職員はチラシと見比べて、アレルゲン表記の品目を直せる（減らすこともできる。SR-19 と同じく、品目を減らせるのは職員の操作だけ）。直したら分類し直す
- 直せるのは、**今回のチラシから読んだ品目**（3.4 の 1）だけ。説明文の探す言葉（2）・商品名の探す言葉（3）・マスタの記録（4）で当たったものは、取り込みの画面からは消せない（SR-14。マスタの記録はパッケージでの確認で直す）
- 読み取りの検証の「この品目の表記はない」という指摘で、品目を自動で消さない（SR-19）

### 3.7 外した掲載品

| ID | 要件 |
| --- | --- |
| FR-IMPORT-20 | Claude は読み取りのときに、**食品以外**の掲載品（洗剤・日用品・おもちゃなど）にも、ほかの商品と同じ項目を読んだうえで「食品以外」の印と理由を付けて返す（「戻す」で戻せるように）。アプリはその商品を外す。外した掲載品は分類せず、一覧の下の「外した掲載品」に商品名と理由を並べる（黙って消さない） |

| FR-IMPORT-22 | 外した掲載品は今週の商品に入れず、商品の値（価格・内容量・入数など）も変えない。ただし 3.5 の食い違いの「参考」の記録だけは足す（記録は確認を増やす方向だけ） |

### 3.8 注意（再入力にせず、自動で進めるもの。D-101）

次のものは、分類を変えずに行に「注意」として出すだけにし、アプリが決めた値で取り込みを進める。職員は直してもよい（行の詳細欄で直すと分類し直す）が、直さなくても取り込める。

| 注意 | 自動で決める値 | 行に出す文（例） |
| --- | --- | --- |
| 一致した商品と内容量・入数の候補が違う（FR-IMPORT-12） | チラシの値で上書きする（入数は入数の候補）。過去の週は上書きせず、マスタが空のときだけ埋める | 「内容量が変わりました（マスタ 12個入り → チラシ 10個入り）。届いたらパッケージの原材料も見てください」 |
| 読み取りの検証（FR-FLYER-03g）の指摘 | 読み取った値のまま。アレルゲンについては、指摘で品目を消したり「含まない」にしたりしない（SR-19） | 指摘の内容と理由（FR-FLYER-03h。当てはまる項目のそばにも出す）。アレルゲンの読み落としの指摘は、ほかの注意より先に並べる |
| 読み取りの検証ができなかった（取り込みの全件） | 読み取った値のまま | 一覧の上に「読み取りの検証ができませんでした。献立の確定のときに、チラシの表記と見比べてください」 |
| 二重に読んだ商品の値の食い違い（FR-IMPORT-06） | 先に読んだ値を使う。アレルゲンの品目・説明文の探す言葉・品目の分からない語は和集合のまま | 「2回読みました。税込価格が 298円 / 398円 と違います。298円 を使います」 |
| 税込価格と税抜価格が合わない（FR-FLYER-03f の整合） | 読み取った税込価格を使う（FR-FLYER-03b） | 「税込398円が税抜298円と合いません。税込398円を使います」 |
| 税抜価格が1未満（0・負の値） | 読めなかった扱い（空）にする。既存の商品のマスタの税抜価格は空で上書きしない | （出さない。読み取りの時点で空にする） |
| 内容量が読めない | 空のまま取り込む。既存の商品のマスタの内容量は空で上書きしない | 「内容量が読めませんでした」 |
| 注文番号が読めない | 空のまま取り込む（掲載品の写しの注文番号は空）。既存の商品のマスタの注文番号は空で上書きしない | 「注文番号が読めませんでした。注文のときにチラシで確かめてください」 |
| 入数の候補が内容量の表記と合わない（FR-FLYER-03f のアプリの検証） | 入数の候補を使う | 「入数の候補（10）が内容量の表記と合いません。10 を使います」 |
| 入数を入れ直した（FR-IMPORT-11）・手入力（D-73） | 職員が入れた値 | 「読み取りの検証を通っていません」 |

- 注意はアレルゲンの判定・記録を変えない。注意があっても、分類は 3.2 で決まる
- 注意の文は、使った値が分かるように書く（職員が値を直したいときに、どれを直せばよいか分かるように）
- 注意は取り込みの画面の中だけで出し、記録（`allergen_checks`）や掲載品の写しには残さない（チラシの表記の原文は写しに残す。5.4）
- 「取り込める」の商品が、取り込みを終えるときに失敗する条件は作らない。商品に登録できない読み取りの値（1未満の税抜価格・空のタグ・選べる語にない味・種類のタグ）は、読み取りの時点で読めなかった扱いにして除く（Claude の出力は信用しない）

| ID | 要件 |

## 5. 確定

### 5.1 取り込みを終える（D-101）

確定の操作は、一覧の上の「**取り込みを終える**」の1つだけにする。押すと、サーバーが全件の分類を求め直したうえで、次をまとめて行う。

| 分類 | 取り込みを終えたときにアプリがすること |
| --- | --- |
| 🔴 使えない | 今週の商品に入れない。商品の値は変えない。3.5 の食い違いの「参考」の記録だけは足す |
| 🟠 再入力 | 確定しない（今週の商品に入れない）。3.5 の食い違いの「参考」の記録だけは足す |
| 🟢 取り込める（新しい商品） | 商品を新しく登録し、チラシの品目で「参考」の記録を足す（表記なしなら「参考（表記なし）」。**どの品目も「含まない」にしない**）。おやつの分類・タグは Claude の候補（直していればその値） |
| 🟢 取り込める（既存の商品） | 一致した商品の税込価格・税抜価格・注文番号・最後に載った週を上書きする（FR-FLYER-07。過去の週のときは上書きしない）。内容量・入数は 3.8 のとおり上書きする（過去の週は空のときだけ埋める。FR-IMPORT-12）。読めなかった値（空）では上書きしない。記録は 03 の 3 の表と 3.5 のとおり。おやつの分類・タグはマスタの値を使い、上書きしない |
| 外した掲載品 | 今週の商品に入れない。商品の値は変えない。3.5 の食い違いの「参考」の記録だけは足す |

- 取り込めるの商品は、掲載品の写し（`menus.listed_products`）に足す（FR-FLYER-07・06c は変えない）。写しには今週のチラシの表記の原文も持つ（5.4）。取り込んだ商品は一覧に「確定済み」として残す
- 「使えない」「再入力」「外した掲載品」の商品は、掲載品の写しに入れない。一覧の上に「今週の商品に入らない N件（使えない a件・再入力 b件）」と示す（FR-FLYER-06b）。再入力が残っていても取り込みは終えられる（再入力の商品は入らない）。あとで直して、もう一度「取り込みを終える」を押せば取り込む
- 確定済みの商品も直せる（FR-FLYER-06c）。直すと分類し直し、もう一度「取り込みを終える」を押すと上書きする。直した結果が使えない・再入力になった商品は、掲載品の写しから外す（確認する側に倒す）
- 取り込みを終える API は、画面から送られた分類を使わず、サーバーが分類を求め直す。**使えない・再入力・外した掲載品は、画面を通さずに送っても確定しない**
- 取り込みを終える処理は1つのまとまり（トランザクション）で行い、途中でエラーになったら、商品の追加・書き換え・記録の追加・写しの更新を何もしない（03 の 5 のテストから変えない）
- 終えたら、新しく登録した件数・上書きした件数・参考の記録を足した件数・今週の商品に入らない件数を知らせ、手順2（今週の商品）へ進めるようにする
- 行の詳細欄で直している途中（直した内容をまだ送っていない）の商品があるときは、「取り込みを終える」の前に、直した内容を反映するか捨てるかを聞く（直した内容を黙って捨てて、読み取ったままで取り込まないため）
- 名前＋メーカーが同じ行が2つ以上あるときは、1件の商品にまとめて取り込む（2 の FR-IMPORT-06 の補足）。一覧の上の「新しい商品 ○件・登録済み ○件」と、終えたあとの件数は、行の数でなく商品の数で数える
- 同じ商品（名前＋メーカーが同じ）の行のうち、使えない・再入力で今週の商品に入れなかった行のチラシの品目も、今週の商品に入るその商品（この取り込みで取り込む、または写しにある商品）の「参考」の記録に足す（記録がないか「参考」だけの商品で、品目が増えるときだけ。確認済みの商品は 3.5 のとおり）。同じ商品なのに、避ける品目を含むと読んだ行だけが 🔴 になり、取り込んだ商品にその品目が残らないことがないようにする（確認を増やす方向だけ）
- 取り込んだ行の取り込みを取り消したとき（「外す」・取り込み済みの行を直す）は、その商品で取り込んだ行がほかになければ、写しから外し、この取り込みで登録した商品は「使わない」にする。登録済みの商品に上書きした値（税込価格・税抜価格・注文番号・最後に載った週・内容量・入数）は、まだ上書きした値のままの項目だけ、取り込む前の値に戻す（読み違いを商品一覧に残さない。取り込みのあとに商品一覧で直した値は戻さない。FR-IMPORT-22 と同じ考え方）。アレルゲンの記録は戻さない（記録は追加だけ）

### 5.2 なくしたもの（D-101）

D-100 の「まとめて確定・まとめて登録に入れない商品」（表記なしの見比べ前・手入力・入数を入れ直した・検証ができなかった・直している途中・分類か入数の候補がない）はなくす。次の操作・画面もなくす。

- 「使える商品をまとめて確定」「新しい商品をまとめて登録」の2つのボタンと、1件ずつの「確定」「新しい商品として登録」
- 「新しい商品をまとめて登録」のダイアログ（D-98）と、「使える商品をまとめて確定」の確かめのダイアログ
- 表記なしの見比べ（表の上のまとめ・ダイアログ・見比べの印。FR-FLYER-04a・D-97）
- 再入力の「このままでよい」

それぞれの代わり：手入力・入数を入れ直した・検証ができなかった商品は、注意（3.8）を出して取り込める。新しい商品でおやつの分類の候補がない商品は再入力（3.1）、入数の候補がない商品は使えない（3.3）。表記なしの見比べは、献立の確定の確認のチェック（5.4）で行う。

### 5.3 「再入力」での直し方

- 詳細欄のフォームは、再入力の理由に当たる欄だけを開いて出し、理由（「税込価格が読めませんでした」「メーカーが読めませんでした」など）をその欄のそばに出す。ほかの欄は1行の要約にまとめ、「ほかの項目も直す」で開く
- 「このままでよい」はない。理由の欄を直すと、サーバーが分類し直して返す
- 商品名・メーカーを直したら照合し直す（一致する商品が変わることがある）
- 品目の分からない語は、品目を選ぶか「対応する品目なし」を選ぶ
- 表記なしなのに一致した商品の記録で特定原材料を「含む」商品は、チラシで表記を探して、アレルゲン表記の品目を入れる（品目を入れれば表記なしでなくなる）。チラシに本当に表記がないときは「外す」（今週の商品に入れない）
- 直したらサーバーが分類し直して返す。結果が「使えない」になることもある（直した表記に避ける品目があったなど）

## 10. テストで必ず確かめること（xUnit）

**照合**

- 正規化した商品名とメーカーが両方同じときだけ一致する。商品名が同じでメーカーが違えば一致しない
- 全角・半角、カタカナ・ひらがな、「CO・OP」「コープ」、記号・空白の違いでは一致する（メーカーにも同じ正規化がかかる）
- 内容量が違っても一致する（そのうえで注意が出て、取り込めるになる）
- メーカーが空のチラシの商品は照合せず再入力になる。メーカーが空のマスタの商品とは一致しない
- 一致が2件以上のとき、最後に載った週が新しい方、同じなら更新日時が新しい方を使う
- 同じ商品を2回読んだら1件にまとめ、アレルゲンの品目は和集合になる。価格が食い違えば先に読んだ値を使い、注意が出る（再入力にならない）

**分類**

- 分類は 使えない・再入力・取り込める の3つだけになる（要確認・使えるは返さない）。新しい商品も既存の商品も取り込めるになり、新しい商品かどうかは印で分かる
- 入数の候補がなく、一致した商品にも入数がない → 使えない。一致した商品に入数があれば使えないにならない
- 入数を入れると分類し直され、ほかの条件に当たらなければ取り込めるになる
- チラシの表記・説明文の探す言葉・商品名の探す言葉・一致した商品の記録のどれか1つで避ける品目に当たれば使えない（それぞれ1件ずつ）
- 一致した商品が「使わない」なら使えない
- 使えない ＞ 再入力 ＞ 取り込める の順になる（例：税込が読めず避ける品目を含む → 使えない。税込が読めず一致がない → 再入力）
- 商品名・メーカー・税込価格が空 → 再入力。直すと分類し直す
- 品目の分からない語がある → 再入力。品目を選ぶ（または対応する品目なし）と分類し直す
- 表記なしと読んだのに、一致した商品の有効な記録で特定原材料を含む → 再入力。品目を入れると分類し直す
- 新しい商品でおやつの分類の候補がない → 再入力
- 次のものは再入力にならず、注意が出て取り込めるになる（ほかの条件に当たらなければ）：一致した商品と内容量か入数の候補が違う・読み取りの検証の指摘・検証ができなかった・二重に読んで値が食い違う・税込と税抜が合わない・内容量が読めない・注文番号が読めない・入数の候補が内容量の表記と合わない・手入力
- 読み取りの検証のアレルゲンの指摘（「この品目の表記はない」）で、読んだ品目は消えない（SR-19）
- 一致した商品の記録が「参考」「要再確認」でも、避ける品目がなければ「取り込める」になる（アレルゲンの判定は 🟡 のまま変わらない）
- 一致した商品に記録がない（不明）とき、チラシの品目に避ける品目がなければ取り込める、あれば使えない
- 避ける品目が1つもないとき、避ける品目による使えないは起きない

**略記**

- 「麦」「え」「か」「く」「そ」「落」「カ」が、小麦・えび・かに・くるみ・そば・落花生・カシューナッツに当たる
- ひらがなの「か」はかに、カタカナの「カ」と半角の「ｶ」はカシューナッツに当たる。「か」がカシューナッツに、「カ」がかにに当たらない
- 「エ」「ソ」「ク」（カタカナ）は当たらず、品目の分からない語になる
- 「くっきー」「えびせん」「カカオ」は略記で当たらない（語全体の一致だけ）
- Claude が品目を返さなくても、表記の「カ」からカシューナッツが足される。Claude が返した品目は消えない

**確認済みとの食い違い（3.5）**

- 確認済みの商品で、チラシに避ける品目が増えたら使えないになり、取り込みを終えると「参考」の記録が足され、判定が「含む」（エラー）になる
- 避ける品目でない品目が増えたら取り込めるのまま、取り込みを終えると「参考」の記録が足され、判定が 🟡 になる
- 取り込みを終える前に職員が表記を直して食い違いがなくなれば、記録は足されない
- 使えない・再入力・外した掲載品の商品も、食い違いがあれば取り込みを終えるときに記録が足される（今週の商品には入らない）。表記を直してから外せば足されない
- 取り込みを2回終えても、同じ食い違いの記録は二重に足されない
- 確認済みの商品で、チラシの品目が確認済みの「含む」の中に収まっていれば、記録は足されない（今と同じ）

**取り込みを終える**

- 使えない・再入力・外した掲載品は、取り込みを終える API でも確定しない（画面を通さずに送っても。サーバーが分類を求め直す）
- 取り込めるの商品は、手入力・入数を入れ直した・検証ができなかった・表記なしの商品も含めて、1回の操作で全件取り込まれる
- 新しい商品の記録は、どの品目も「含まない」にしない。表記なしは品目が空の「参考」（表記なし）になり、「安全」にならない
- 既存の商品の価格・税抜価格・注文番号・最後に載った週は上書きされ、おやつの分類・タグは上書きされない。過去の週の取り込みでは上書きされない
- 内容量・入数がマスタと違えば、チラシの値で上書きされる。過去の週では上書きされず、マスタが空のときだけ埋まる。読めなかった（空の）内容量・注文番号ではマスタを上書きしない
- 確定済みの商品を直して使えない・再入力になったら、もう一度終えたときに掲載品の写しから外れる
- 取り込みを終える処理がエラーになったときは、商品の追加・書き換え・記録の追加・写しの更新を何もしない
- 手入力の行と読み取った行（または直して同じになった行）の名前＋メーカーが同じなら、終えると商品は1件だけ登録され、品目は「参考」の記録の和集合になる。2行とも取り消すと、写しから外れ「使わない」になる
- 同じ商品の行が避ける品目で使えないなら、取り込んだ商品の「参考」の記録にその品目が入り、判定は入れられないになる
- 税抜価格が1未満なら読めなかった扱いになり、取り込めるの商品はほかの商品と一緒に取り込まれる。空のタグ・選べる語にない味のタグがあっても取り込める
- 取り込みを取り消すと、登録済みの商品に上書きした値は前の値に戻る。取り込みのあとに商品一覧で直した値は戻らない

**献立の確定（5.4）**

- 掲載品の写しに、チラシの表記の原文が入る。表記なしなら「表記なし」。職員が表記を直していれば直した原文
- 献立の確定の確認のチェックが要る商品に、その週の写しの表記の原文が付く。原文が null（古いデータ）なら付かない
- 表記の原文があってもなくても、確定の条件（エラー・確認のチェックの要否）は変わらない

## 11. E2E（Playwright）で確かめること

- ダミーのチラシ（`samples/flyers/`）を取り込むと、3つの分類のタブ（再入力・取り込める・使えない）に件数が出て、再入力 → 取り込める → 使えない → 確定済みの順に並ぶ
- 取り込めるの行に、新しい商品の印か一致した商品の名前と、注意が出る
- 「取り込みを終える」を1回押すと、取り込めるの商品（新しい商品も既存の商品も）が今週の商品に入る。使えない・再入力の商品は今週の商品に入らない
- 再入力の商品の税込価格を入れると、取り込めるに変わる。「このままでよい」・表記なしの見比べ・まとめて確定のボタンは出ない
- 略記の表記（「（乳・麦）」「（カ）」）の商品が、補正した品目で表示される
- 「外す」「戻す」で外した掲載品との間を行き来できる
- 献立の確定のダイアログで、🟡 要確認の商品の確認のチェックに、今週のチラシの表記の原文（「表記なし」を含む）と「チラシの表記と見比べて、パッケージが届いたら原材料を確かめてください」が出る

ダミーのチラシには、各分類と注意に当たる商品（入数が分からない大袋、税込が読めない商品、メーカーのない商品、「カ」の表記の商品、一致するが内容量の違う商品、表記なしの新しい商品など）を入れる（`samples/flyers/*.json` を直して `tools/build-samples/build.py` で作り直す）。
