# 画面の E2E（Playwright）

画面の要件を、要件 ID つきのテストで確かめます（D-87・T0-15）。

## 走らせ方

```
cd src/oyatsubiyori.client
npm run e2e
```

- サーバーは `ASPNETCORE_ENVIRONMENT=E2E` で起動します（`https://localhost:7175`）。DB（`oyatsu-biyori.e2e.db`）は毎回作り直し、TD-02 のダミーデータを入れます
- **Claude は偽物**です（`OyatsuBiyori.Server/E2E/FakeClaudeServices.cs`）。チラシの読み取りは `samples/flyers/flyer-02.expected.json`（設定の `E2E:FlyerSample`）を返します（画面から送る画像はブラウザで JPEG に描き直されるので、どのファイルを選んでもこのチラシの正解が返ります。画像ごとに正解を選び分けるのは、PNG をそのまま送る読み取り精度の測定の自己確認だけです）。費用がかからず、毎回同じ結果になります。Biz の検証・アレルゲンの判定は本物を通します
- 偽の読み取りの検証は、いつも1件目に「入数」の指摘を1つ返します（D-101 で、1件目は「取り込める」のまま注意が出ます）。商品の照合に Claude は使いません（D-100。名前＋メーカーの完全一致だけ）
- 偽の Claude とダミーデータは E2E の環境でだけ登録されます。本番（環境名・接続文字列・IIS）では `DemoDataGuard` が止めます
- 画面は Vite の開発サーバー（`https://localhost:60235`）から開きます
- 初めて走らせるときは、ブラウザを入れます：`npx playwright install chromium`

## プロジェクト

| 名前 | 中身 |
| --- | --- |
| setup | 最初に1回ログインして、状態を `e2e/.auth/state.json` に保存する |
| pc | 1280×800 |
| mobile | Chromium のスマホの幅（Pixel 7） |

同じ DB を使うため、1つずつ順に走らせます（`workers: 1`）。テストは、前のテスト（PC）で変わったデータでも通るように書きます。

## 決まり

- テストのファイルは画面ごと（`sc-09-menu-edit.spec.ts` など）
- テストの名前は要件 ID から始め、満たすべき条件を日本語で書く（`FR-MENU-14 🔴 の商品を入れると確定できない`）
- 要素は役割と文言で探す（`getByRole`・`getByText`）。CSS のクラスや DOM の構造に頼らない
- 画面ごとに PC とスマホの画像を1枚ずつ `e2e/screenshots/` に撮る（`captureScreen`。目で見る用で、ピクセルの比較はしない。iOS Safari は実機で確かめる）
- 使うデータは TD-02 のダミーデータだけ

## チラシ取り込みの分類（D-101）

`flyer-02` の20商品とダミーデータ（ナッツ類を避ける）で、取り込みの分類は次のようになります（何も登録していない DB で最初に取り込んだとき。[09. チラシ取り込みの分類](../../../docs/requirements/09-flyer-import.md)）。一覧は19件で、並びは 再入力 → 取り込める → 使えない → 確定済み です。取り込めるの商品は、「取り込みを終える」1回でまとめて取り込みます（新しい商品は登録し、登録済みの商品は上書きする）。

| 分類 | 商品（注文番号） | 理由・注意 |
| --- | --- | --- |
| 再入力 | ふんわり 抹茶ロール（428） | 税込価格が読めない（税込375円を入れると取り込める・新しい商品） |
| 再入力 | にこにこ ミニドーナツ（8121） | メーカーが読めない（FR-IMPORT-03。メーカーを入れると取り込める） |
| 取り込める | くまのポッケ ミルクビスケット（8103） | 登録済みと名前＋メーカー・内容量・入数が同じ |
| 取り込める | CO・OP さくさくクッキー（8102） | 注意：登録済みと内容量が違う（10袋入 → 5袋入。FR-IMPORT-12。取り込みを終えるとチラシの値で上書き） |
| 取り込める | チーズ味 ひねりスティック（8107） | 注意：読み取りの検証の指摘（偽の検証が1件目に返す） |
| 取り込める | コンソメ ポテトスティック（426）・どうぶつ型 ココアクッキー（424）・徳用 ミルクチョコ 小分けパック（421） | 注意：入数の候補が内容量の表記と合わない（候補を使う） |
| 取り込める | ことりのさくさくショコラ（8104）ほか、一致する商品がない新しい商品 | 「新しい商品」の印。表記なしの3件（のりしお・ピピ ラムネ・根菜チップス）は、品目が空の「参考（表記なし）」で登録し、今週の商品では 🟡 |
| 使えない | うすしお ポテトチップス 大袋（8110） | 入数が分からない（入数を入れると取り込める。注意：検証を通っていない。FR-IMPORT-10・11） |
| 使えない | こつぶ しお豆スナック（427） | 表記「（乳・カ）」の「カ」＝カシューナッツ（FR-IMPORT-32） |
| 外した掲載品 | キッチン スポンジ 3個（429） | 食品以外（FR-IMPORT-20） |

- `flow-hazelnut.spec.ts`（PC だけ）が先に来週の取り込みを終えるので、取り込めるの商品はすべて登録済みになり、さくさくクッキーの内容量は5袋入に上書きされます。ショコラはパッケージでヘーゼルナッツが見つかるので、`sc-09-menu-edit.spec.ts` では「使えない」（登録済みの商品の記録）になります。再入力の2件（抹茶ロール・ドーナツ）と使えないの商品は登録されません
- 献立の確定のダイアログ（再来週）では、掲載品の写しにダミーの表記の原文（小魚あられ・ラムネは「表記なし」、寒天は「もも」。ほかは D-101 より前と同じ null）を入れてあり、🟡 のチェックに「今週のチラシの表記：」を添えます
- スマホのテストは PC のあとに同じ DB で走るので、PC で登録した商品には「新しい商品」の印が付きません。PC で入数を入れて登録した大袋は、スマホでは商品一覧の入数で「取り込める」になります。テストは件数や分類を決め打ちせず、PC だけで確かめるところは `testInfo.project.name` で分けます
