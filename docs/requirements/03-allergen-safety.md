# 03. アレルゲンの扱い（安全要件）

子どもの安全に直結するため、この文書の要件は他のすべての要件に優先する。
**迷ったら「確認する側」に倒す。**

## 1. 基本方針

- AI（Claude）の判定は**候補**であり、確定は必ず職員が行う
- アレルゲン情報が確かでない商品を、「食べられる」とは扱わない
- 「表示なし」を「含まない」とみなさない場合がある（推奨20品目と、表示義務の経過措置中のカシューナッツ）
- **29品目に入らない食材もある**（ヘーゼルナッツ・ペカンナッツなど）。29品目のチェックだけで「食べられる」と判断しない
- 情報はいつか古くなる（リニューアルで原材料が変わる）。確認には期限を設ける

### 現場で起きたこと（この設計の根拠）

> ナッツを避けたかったのに、ヘーゼルナッツペーストが入ったお菓子を選んでしまったことがある。

ヘーゼルナッツは29品目（2026年3月までは28品目）に入っていないため、アレルゲン表示（「一部に〜を含む」）に出てこない。原材料名には「ヘーゼルナッツペースト」と書かれているが、アレルゲン表示だけを見ると見落とす。
また「ナッツ」は1つの品目ではない。29品目では、くるみ・カシューナッツが特定原材料、アーモンド・マカダミアナッツ・ピスタチオが推奨品目で、それ以外のナッツは対象外になっている。

## 2. 対象のアレルゲン

品目は制度改正で変わることがあるため、**コードに直書きせずマスタデータとして持つ**。実装時に消費者庁の最新情報を確認する。

> 2026年4月1日の食品表示基準の改正で、28品目から **29品目** に変わった（カシューナッツを特定原材料に変更、ピスタチオを特定原材料に準ずるものに追加）。カシューナッツの表示義務には経過措置があり、**2028年4月1日に完全義務化**される。それまでは、カシューナッツを含んでいても表示されていない商品がありうる（2026-11-03 確認）。

### 2.1 法令上の29品目

| 区分 | 品目 |
| --- | --- |
| 特定原材料（表示義務・9品目） | えび、かに、くるみ、小麦、そば、卵、乳、落花生（ピーナッツ）、カシューナッツ（経過措置中。2028-03-31 までは表示がないことがある） |
| 特定原材料に準ずるもの（表示推奨・20品目） | アーモンド、あわび、いか、いくら、オレンジ、キウイフルーツ、牛肉、ごま、さけ、さば、ゼラチン、大豆、鶏肉、バナナ、ピスタチオ、豚肉、マカダミアナッツ、もも、やまいも、りんご |

- マスタの各品目に **「表示が確実でない」**（`label_not_guaranteed`）の印を持たせる。推奨20品目と、経過措置中のカシューナッツに付ける。この印のある品目は「表示なし＝含まない」とせず、SR-06 の「メーカーへの確認が必要」の対象にする
- 経過措置が終わったら（2028-04-01 以降）、マスタのカシューナッツの印を外す（コードは変えない）

### 2.2 施設で追加する品目

29品目以外で、施設として避ける食材。マスタに追加・編集できる。初期データの例：

| 品目 | 原材料名で探す言葉（例） |
| --- | --- |
| ヘーゼルナッツ | ヘーゼルナッツ、ヘーゼルナッツペースト、ジャンドゥーヤ、プラリネ |
| ペカンナッツ | ペカン、ピーカン |
| ブラジルナッツ | ブラジルナッツ |
| ココナッツ | ココナッツ、ココナツ |
| 松の実 | 松の実、松のみ、パインナッツ |

- 各品目に「原材料名で探す言葉」を持たせ、原材料表示のテキストから**アプリ側で文字列検索**する（Claude の判定とは別に、二重に確かめる）
- 「プラリネ」「マジパン」のように、名前から中身が分かりにくい原材料も言葉に入れる。漢字の表記（胡桃・落花生・松の実など）も入れる
- 探す言葉は商品名にもかける（SR-14）ため、商品名で誤って当たりやすい短い言葉（「乳」「卵」など）は登録しない。特定原材料の乳・卵などはアレルゲン表示で確かめる
- 29品目の木の実（くるみ・カシューナッツ・アーモンド・マカダミアナッツ・ピスタチオ）にも「探す言葉」を持たせる（例：アーモンドに「マジパン」「アーモンドプードル」）。推奨品目は表示されないことがあるため、原材料の全文からも探す（SR-14 は追加品目に限らず、避ける品目すべてに効く）

### 2.3 グループ

避ける品目の設定で、関連する品目をまとめて選べるようにする。

| グループ | 含む品目 |
| --- | --- |
| ナッツ類（すべて） | くるみ、アーモンド、カシューナッツ、マカダミアナッツ、ヘーゼルナッツ、ピスタチオ、ペカンナッツ、ブラジルナッツ、松の実、ココナッツ、落花生（ピーナッツ） |
| 甲殻類 | えび、かに |

- グループを選ぶと、含まれる品目がすべて選ばれる（そのあと個別に外せる）
- 現場では「ナッツ類すべて」を避けているため、落花生（植物としては豆類）とココナッツも初期値でグループに含める（[Q-18](07-open-questions.md)）。不要な品目は、職員が個別に外す
- 栗はグループに含めない（一般に「ナッツ類」として扱われないため）。避ける場合は個別に選ぶ

### 2.4 コープのカートの絞り込みとの関係

コープの注文サイトには、カートに入れるとアレルギーのある商品を除外する機能がある（[Q-15](07-open-questions.md)）。

- この機能が対象とする品目（29品目のどこまでか、2.2 の品目を含むか）は分からない。ヘーゼルナッツのような29品目外の食材は、除外されない可能性が高い
- そのため、**コープの絞り込みを通ったことを「確認済み」の根拠にしない**。使う場合も、情報源「コープのサイト」として「参考」扱いにする
- このアプリは注文と連携しない。献立を決めたあとの発注時に、コープの絞り込みをもう一段の確認として使うのは構わない（職員への案内として書く）

## 3. ステータス

| ステータス | 意味 | 献立での扱い |
| --- | --- | --- |
| 確認済み | 職員がパッケージの原材料表示で確認した（期限内） | 使える |
| 要再確認 | 確認済みだが、確認日から再確認期間（既定90日）を過ぎた | 警告して確認を求める |
| 参考 | コープのサイト・チラシの表記など、パッケージ以外の情報（チラシに表記がない「表記なし」を含む） | 警告して確認を求める |
| 不明 | 情報がない | 警告して確認を求める。**避ける品目が1つでも設定されていれば使わない** |

- 「要再確認」は保存するステータスではなく、最新の「確認済み」記録の日付から**表示時に求める**
- 現在のステータスは、その商品の**最新の確認記録**で決まる。記録のない商品が「不明」で、**「不明」の記録は作らない**（保存するステータスは「確認済み」「参考」の2つ）
- ステータスの名前は判定の説明のための言葉で、画面では 5 の区分（🔴 使えません / 🟡 要確認 / 🟢 使えます）と理由で見せる（6）。ステータスの名前を画面に出すのは、商品詳細のアレルゲン確認の履歴だけ
- **「含む」品目は、最新の記録1件ではなく「有効な記録」から求める**。有効な記録 = 最新の「確認済み」の記録と、それより後のすべての記録（「確認済み」がなければ、すべての記録）。「含む」はその和集合とする。つまり**「参考」の記録で「含む」が減ることはなく、減らせるのはパッケージによる新しい「確認済み」の記録だけ**（チラシの読み落としで、前に分かっていた品目が消えないようにする。SR-19 と同じ考え方）
- チラシから取り込んだ商品は、アレルゲン表記がなくても「参考（表記なし）」として記録する。「含む」品目は空で、どの品目も「含まない」とはしない（[FR-FLYER](02-functional.md#3-チラシ取り込みfr-flyer) の受け入れ条件）。チラシを通さずに商品を登録する機能はない（FR-PROD-10 は欠番）ため、ふだん「不明」は起きない。データの不整合などに備えて、判定には残す
- 「参考」の記録では、「含む」品目だけを保存する（`allergen_check_items` に行がない品目は「未確定」で、「含まない」ではない）
- チラシから得る品目は、アレルゲン表記に書かれた品目と、説明文に避ける品目の「探す言葉」が当たった品目を合わせたもの（以下「チラシの品目」）。説明文そのものは保存せず、当たった言葉を `source_note` に残す

チラシを取り込んだときに「参考」の記録を追加するかは、次の表で決める（毎週の取り込みで「確認済み」が「参考」に戻らないようにする）。

| その商品の記録 | チラシを取り込んだとき |
| --- | --- |
| 記録がない | 「参考」の記録を追加する（チラシの品目がなければ「表記なし」） |
| 過去に「確認済み」がある（期限切れを含む） | 追加しない。チラシの品目に、有効な記録で「含む」になっていない品目があれば SR-20 |
| 「確認済み」はなく、「参考」の記録がある | チラシの品目に、有効な記録で「含む」になっていない品目があるときだけ追加する（品目が減っても追加しない） |
- 新しい商品は届くまでパッケージを撮れないため、献立の確定時には「参考」の商品が残るのが普通である。届いてから確認し、問題があれば SR-17 で献立に戻って直す

## 4. 安全要件

| ID | 要件 |
| --- | --- |
| SR-01 | 「食べられる」と判定するのは、ステータスが「確認済み」かつ期限内で、施設の避ける品目を含まない場合だけとする |
| SR-02 | 「確認済み（期限内）」以外の商品を献立に入れる場合は、必ず警告を表示する |
| SR-03 | Claude の判定結果を、そのまま「確認済み」として保存しない。「確認済み」にできるのは職員の操作だけとする |
| SR-04 | 献立の確定時、「確認済み（期限内）」以外の商品があれば一覧で示し、職員が商品ごとに警告の理由と次にすること（届く前の商品なら「届いたらパッケージで確認する」）を確かめたことを明示的に操作しない限り確定できない（6.3） |
| SR-05 | 照合で「味違い」「内容量違い」と判定された商品は、別の商品として登録し、アレルゲン確認を引き継がない |
| SR-06 | 避ける品目に「表示が確実でない」品目（推奨20品目・経過措置中のカシューナッツ）が含まれる場合、その品目が「表示なし（含まない）」となっている商品には「メーカーへの確認が必要」と表示する |
| SR-07 | アレルゲン確認の記録は追加のみとし、更新・削除しない（誤りは新しい記録で訂正する） |
| SR-08 | 確認記録には、確認日時・確認者・情報源（パッケージ / コープのサイト / チラシ / その他）を必ず残す |
| SR-09 | 全員が同じおやつを食べるため、「不明」の商品は、Claude に献立を作らせる段階で候補から除く（避ける品目が1つでも設定されている場合） |
| SR-10 | 施設の避ける品目を含む商品は、献立に入れられない。手動で入れようとした場合は、含んでいる品目を表示し、確定できないようにする（一部の子だけ別のおやつを出す運用はしない） |
| SR-11 | 原材料表示の「同一工場で製造」「コンタミネーション」の注意書きは、Claude が読み取った場合に記録して表示する（判定は職員に委ねる） |
| SR-12 | 「確認済み」の記録には、原材料表示の全文を必ず残す。全文がない記録は「確認済み」にできない。全文は Claude が読み取ったもの（`raw_ingredients_ocr`）と、職員が見比べて直したもの（`raw_ingredients`）の両方を残す。読み違いは職員が直せる。Claude が使えないときは、職員が全文を手で入力して「確認済み」にしてよい |
| SR-13 | 施設で追加した品目（2.2）が避ける品目に含まれる場合、その品目は**原材料表示の全文で確かめる**。アレルゲン表示（「一部に〜を含む」）だけで判断しない |
| SR-14 | **商品名**、または有効な記録の原材料表示の全文（`raw_ingredients_ocr` と `raw_ingredients` の両方）に、施設の避ける品目の「探す言葉」が含まれていれば、ステータスや職員の確定内容にかかわらず「含む可能性あり」とし、献立に入れられない（例：「ヘーゼルナッツペースト」「ヘーゼルナッツクッキー」）。商品名で調べるのは、全文のない「参考」の商品でも29品目外の食材を見落とさないため（チラシの説明文は取り込みのときに調べ、「チラシの品目」に入れる）。**当たったものを職員が取り消す手段は作らない**（確認する側に倒す）。誤って当たって使えない商品は「使わない」にする。誤検出が多ければ、試用（HK-TRIAL）のあとで見直す |
| SR-15 | 職員がアレルゲンを確定するときは、29品目に加え、避ける品目に含まれる施設の追加品目もすべて「含む / 含まない」を確定させる |
| SR-16 | 避ける品目が増えた場合、その品目について確定していない「確認済み」の商品は「未確認の品目あり」として警告する |
| SR-17 | アレルゲン確認の記録・避ける品目や探す言葉の変更の結果、商品の判定が「入れられない」（5 の判定。含む・含む可能性あり・不明）になったら、その商品を使う今日以降の献立（下書き・確定）に警告を出す。警告は、職員が献立からその商品を外すか、判定が「入れられない」でなくなるまで消さない。判定が警告の範囲で変わった場合（安全 → 要再確認、参考 → 未確認の品目あり など）は、確定済みの献立は確定のままとし、今日以降の日で「確認し直し」として示す（SR-22）（[FR-MENU-36](02-functional.md#56-商品が届いてからの確認)） |
| SR-18 | Claude の献立案をアプリが検証し、問題を Claude に返して直させる場合（[FR-MENU-15](02-functional.md#52-献立案の作成)）でも、最終的な判定はアプリの判定を使う。Claude の返答で判定を変えない |
| SR-19 | チラシの読み取りの検証（[FR-FLYER-03g](02-functional.md#3-チラシ取り込みfr-flyer)）でアレルゲンについて採用するのは、**確認を増やす方向の指摘だけ**とする。「表記を読み落としている」「この品目の表記がある」は警告として示し、「この品目の表記はない」「読み取った表記は誤り」という指摘で、読み取った品目を消したり「含まない」にしたりしない。外すのは、職員がチラシと見比べて操作した場合だけとする |
| SR-20 | 「確認済み」の商品で、チラシの品目（アレルゲン表記と、説明文で探す言葉が当たった品目。3 を参照）に、有効な記録で「含む」になっていない品目があるとき（例：チラシに「（乳）」、確認済みでは乳を含まない）は、取り込みの画面で食い違いを示す。その品目が施設の避ける品目なら、**チラシの表記を「含む」とした「参考」の記録を追加する**（献立に入れられなくなる。パッケージで確認し直せば戻る）。避ける品目でなければ、職員が「確認し直す（参考の記録を追加）」か「チラシの誤りとして扱う」を選ぶ（既定は確認し直す） |
| SR-21 | 献立の確定で止めるもの（エラー）と、確認すれば確定できるもの（警告）を、5 の判定結果で分ける。エラーの商品は、職員の確認の操作があっても確定できない |
| SR-22 | 確定時に職員が確認した警告は、確認したときの判定を記録する。その後に判定が変わった場合（参考 → 含む可能性ありなど）や、商品を入れ替えた場合は、確認をやり直させる |

## 5. 判定ロジック（Biz に置き、xUnit でテストする）

判定の結果は、献立での扱いによって3つに分ける。**ステータスより先に「含む」を調べる**（「参考」でチラシに「（卵）」とある商品を、警告だけで使えるようにしないため）。

| 区分 | 判定 | 献立での扱い |
| --- | --- | --- |
| 入れられない（エラー） | 含む / 含む可能性あり / 不明（避ける品目が1つでもあるとき） | Claude に渡す候補・入れ替え案から除く。手動で入れると理由を表示し、確定できない（職員の確認の操作でも確定できない） |
| 警告（確認すれば使える） | 参考 / 要再確認 / 未確認の品目あり / 不明（避ける品目がないとき） | 候補にしてよい。確定時に商品ごとの確認が要る（SR-04・SR-22） |
| 安全 | 上のどれでもない | そのまま使える。「メーカーへの確認が必要」を添えることがある（SR-06） |

```
商品の判定(商品, 避ける品目, 今日):
    最新     = 商品の最新の確認記録（なければ「なし」）
    確認済み = 最新の「確認済み」の記録（なければ「なし」）
    有効     = 確認済み と、それより後のすべての記録（確認済みがなければ、すべての記録）
    含む品目 = 有効 の「含む」品目の和集合
    全文     = 有効 の原材料の全文（読み取り・職員の修正の両方）
    もし 避ける品目 ∩ 含む品目 ≠ 空                             → 含む（エラー）
    もし 正規化した商品名 か 全文 に、避ける品目の「探す言葉」がある → 含む可能性あり（エラー）
    もし 最新がない:
        もし 避ける品目が1つでもある                           → 不明（エラー）
        それ以外                                                → 不明（警告）
    もし 最新.ステータス = 参考                                 → 参考（警告）
    もし 今日 - 確認済み.確認日 > 再確認期間                     → 要再確認（警告）
    もし 避ける品目のうち、確認済み で確定していない品目がある     → 未確認の品目あり（警告）
    もし 避ける品目に「表示が確実でない」品目がある               → 安全（「メーカーへの確認が必要」を添える）
    それ以外                                                    → 安全
```

- 「今日」と確認日は、日本時間の日付で比べる（時刻は使わない。[NFR-OPS-07](06-non-functional.md#4-信頼性運用nfr-ops)）。Biz には時計を外から渡し、テストで日付を固定する
- 判定は保存せず、表示・検証のたびにこの関数で求める（避ける品目・探す言葉・再確認期間が変わっても、すぐに反映されるようにする）
- 「探す言葉」・商品名・原材料の全文は、**同じ正規化**（NFKC → カタカナをひらがなに → 空白・改行・記号を除く）をしてから部分一致で探す。パッケージの全文は語の途中で改行されることが多いため、改行も除く。「CO・OP」「コープ」の除去は商品の照合だけで使い、ここでは使わない

### テストで必ず確かめること

- 記録がない商品は安全と判定されない
- 「参考」「不明」の商品は、含む品目が空でも安全と判定されない
- **「参考」で避ける品目を「含む」商品は、警告ではなくエラー（入れられない）になる**
- 避ける品目が1つでもあるとき、「不明」はエラーになる。ないときは警告になる
- 商品名に「探す言葉」がある「参考」の商品（例：「ヘーゼルナッツクッキー」）は、全文がなくてもエラーになる
- 職員が直した全文から言葉を消しても、Claude が読み取った全文に言葉があればエラーになる
- 再確認期間の境界（ちょうど90日・91日）の判定
- 最新の記録が「参考」で、それより前に「確認済み」がある場合は、最新（参考）が優先される
- 避ける品目に「表示が確実でない」品目（推奨20品目・経過措置中のカシューナッツ）があるときに、注意表示が出る
- **ヘーゼルナッツの事例**：ヘーゼルナッツを避けているとき、アレルゲン表示が「小麦・乳・大豆」で、原材料に「ヘーゼルナッツペースト」を含む商品は安全と判定されない
- 職員が「ヘーゼルナッツ：含まない」と確定していても、原材料の全文に「ヘーゼルナッツ」があればエラー（含む可能性あり）になる
- 「探す言葉」の検索は、正規化（NFKC・カタカナ／ひらがな・空白と改行と記号の除去）したうえで行い、全角・半角の違いや、「ヘーゼル（改行）ナッツペースト」のような改行で見落とさない
- 「参考」の記録で「乳・卵」→ 次のチラシで「乳」だけになっても、卵は「含む」のまま（エラーのまま）
- 「確認済み」の記録のあとに、含む品目のない「参考」の記録を足しても、確認済みの「含む」は残る
- 新しい「確認済み」の記録で「含まない」にした品目は、それより前の「参考」の「含む」に引きずられない
- 避ける品目に新しい品目を追加したとき、その品目を確定していない商品は安全と判定されない
- 「確認済み」の商品にチラシを取り込んでも、「参考」の記録は追加されない（SR-20 の食い違いがある場合を除く）
- チラシの表記に、確認済みでは「含まない」の避ける品目があるとき、エラーになる（SR-20）
- 確定時に確認した警告は、判定が変わると確認していない状態に戻る（SR-22）

## 6. 画面での表示

職員は判定のルール（3〜5）を覚えなくてよい。画面では、**5 の判定の区分を「3つの表示」**として見せ、そこに**理由**と**次にすること**を添える（D-83）。§3 のステータスの名前（確認済み・参考・不明・要再確認）と細かい判定の名前（未確認の品目あり・含む可能性ありなど）は、判定の説明のための言葉で、画面の主役にしない。

### 6.1 3つの表示

| 表示 | 5 の区分 | 色 | 意味（職員向け） |
| --- | --- | --- | --- |
| 🔴 **使えません** | 入れられない（エラー） | 赤 | 献立に入れられない。献立に入っていれば直す必要がある |
| 🟡 **要確認** | 警告 | 黄 | 献立に入れられるが、確定のときに商品ごとの確認が要る |
| 🟢 **使えます** | 安全 | 緑 | そのまま使える |

- 呼び名は [07 の D-84](07-open-questions.md) で決めた。🟢 を「確認済み」と呼ばないのは、記録のステータス名と同じ言葉になり、「確認済みなのに 🔴（含む）」「確認済みなのに 🟡（要再確認）」が起きて紛らわしいため。「安全」と呼ばないのは、「メーカーへの確認が必要」を添えることがあるため
- 色は**区分で決める**（ステータスでは決めない）。たとえば「不明」は、避ける品目があれば 🔴、なければ 🟡 になる
- 色だけに頼らず、絵文字（またはアイコン）と文字の両方で示す
- 画面に出す文言は、この表と 6.2 の表を正とし、フロントの共通部品（T4-01）だけから出す

### 6.2 理由と次にすること

5 の細かい判定ごとに、表示に添える理由と次にすることを決めておく。**色（区分）を決めるのは 5 の疑似コードで先に決まった判定だが、🔴 の理由は当たったものをすべて並べる**（例：「卵を含みます／原材料に『ヘーゼルナッツ』があります」。SR-10。判定は含む品目と当たった言葉をすべて返す）。

| 細かい判定 | 表示 | 理由（例） | 次にすること（例） |
| --- | --- | --- | --- |
| 含む | 🔴 | 「卵を含みます」 | 「献立には入れられません」。献立に入っていれば「別の商品に替えてください」。（あると良い）「含む」が参考の記録から来ているとき（チラシの表記など）は「パッケージで確認し直せば、表示が変わることがあります」を添える（SR-20） |
| 含む可能性あり | 🔴 | 「原材料に『ヘーゼルナッツ』があります」（商品名で当たったときは「商品名に…」） | 同上。「アレルゲン確認で『含まない』にしても、この表示は消えません」を添える（SR-14） |
| 不明（避ける品目あり） | 🔴 | 「アレルゲンの情報がありません」 | 「パッケージの原材料表示を撮って確認してください」 |
| 参考 | 🟡 | 情報源で書く：「チラシの情報だけです」「チラシにアレルゲンの表記がありません」「コープのサイトの情報だけです」。確認済みの商品に SR-20 で参考の記録を足したときは「チラシの表記が、パッケージでの確認と食い違っています」 | 「届いたらパッケージの原材料表示を撮って確認してください」 |
| 要再確認 | 🟡 | 「前回の確認から○日たちました」 | 「パッケージの原材料表示を撮って、もう一度確認してください」 |
| 未確認の品目あり | 🟡 | 「○○をまだ確認していません」（避ける品目を増やしたあと） | 「パッケージの原材料表示を撮って、○○を確認してください」 |
| 不明（避ける品目なし） | 🟡 | 「アレルゲンの情報がありません」 | 「パッケージの原材料表示を撮って確認してください」 |
| 安全 | 🟢 | なし | なし。避ける品目に「表示が確実でない」品目があれば「メーカーへの確認が必要」を添えることがある（6.3。🟡 にも添える。🔴 には添えない） |

- 🟡・🔴 の商品からは、その場でアレルゲン確認（SC-08）へ進める
- §3 のステータスの名前（「確認済み」「参考」）を画面に出すのは、商品詳細のアレルゲン確認の履歴（記録ごとの情報源とステータス）だけにする

### 6.3 そのほかの表示

- 「メーカーへの確認が必要」（SR-06）は、アレルゲン確認の画面・商品詳細・今週の商品の一覧に小さく添え、献立の日ごとのカードには出さない（ナッツ類を避けていると多くの商品に出るため、ほかの警告が読まれなくなるのを防ぐ）。そのかわり、**献立の確定のダイアログの末尾に1行で必ず出す**（例：「ナッツ類の一部は表示されないことがあります。気になる商品はメーカーに確認してください」）
- **避ける品目が1つも設定されていない**ときは、今週の商品（SC-09 手順2）・商品一覧（SC-06）・献立案（SC-09 手順4）の上部に「避ける品目が設定されていません」と表示し、設定（SC-04）へ進めるようにする（判定は変えない。このときは「含む」「含む可能性あり」「不明（エラー）」が起きないため、すべて 🟢 か 🟡 になる）
- 確定のときの商品ごとのチェックは、警告の理由と次にすることを確かめたことを示す1文にする（例：「☐ フルーツゼリー：チラシの情報だけです。届いたらパッケージで確認します」）。「確認しました」だけの文言にしない（届く前の商品はパッケージを見られないため。SR-04）
- 確定のときに「届いたら確認する」とした商品が、届いたあとも確認されないまま残らないように、献立一覧（SC-10）の上部で「今日以降の献立で使う、パッケージで確認する商品」を最初に示す
- 「確認し直し」（D-71・D-85）のバッジは黄（警告と同じ色）にする
- 警告の文言は、何をすればよいかを含める（例：「パッケージの原材料表示を撮影して確認してください」）
- 画面の目立つ場所に「アレルゲンの最終確認は、必ずパッケージの原材料表示で行ってください」と表示する
- アレルゲン確認の画面では、原材料表示の全文の中で「探す言葉」に当たった部分を強調表示する（例：「ヘーゼルナッツペースト」に色をつける）
