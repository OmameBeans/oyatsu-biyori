# 02. 機能要件

各要件には ID を振る。実装・テスト・コミットメッセージで参照してよい。
アレルゲンに関わる要件は [03-allergen-safety.md](03-allergen-safety.md) の安全要件（`SR-xx`）が優先する。

---

## 1. 条件設定・固定条件（FR-COND）

優先度：**必須**

献立の**固定条件**（アレルギー・予算・人数）を事前に設定する。固定条件はアプリが必ずチェックし、Claude の判断に任せない。
あわせて、同じ商品を続けて出さないための重複ルールも設定する（アプリが警告する）。
アレルギーは「2. 避ける品目（アレルギー）の設定」で設定する。それ以外の条件は、献立を作るときに自然言語で伝える（[5.1](#51-週の要望自然言語の条件)）。

| ID | 要件 |
| --- | --- |
| FR-COND-01 | 通常時の子どもの人数を設定できる（現場は40〜70人程度。ダミーデータもこの規模で作る） |
| FR-COND-02 | **既定の週の予算**（円・税込）を設定できる。献立を作るときにその週の予算として写し、献立ごとに手で上書きできる（[週の予算の扱い](#週の予算の扱い)） |
| FR-COND-03 | おやつを出す曜日を設定できる（既定：月〜金）。献立には、この曜日の日をすべて作る。**祝日はアプリで判断しない**（祝日のマスタは持たない）。休みの日は、要望で伝えるか、日ごとのカードで日の種類を「おやつなし」に切り替える |
| FR-COND-04 | アレルゲンの再確認期間を設定できる（既定：90日） |
| FR-COND-05 | おやつの分類（しょっぱいもの / あまいもの / デザート・飲料）ごとに、同じ商品を出さない期間を設定できる（既定：しょっぱいもの・あまいもの 30日、デザート・飲料 設定なし） |
| FR-COND-06 | 重複についての補足ルールを自然言語で設定できる（任意。例：「ポテトチップスは味違いでも同じ商品として60日あける」「ゼリーは週1回まで」）。献立を作るたびに Claude に渡す。補足ルールで FR-COND-05 の期間を短くすることはできない（アプリの警告は FR-COND-05 の期間で出す） |

### 受け入れ条件

- 人数・予算は1以上の整数のみ受け付け、不正な値はエラーメッセージを表示する
- 変更した条件は、次に作る献立から反映される。作成済みの献立は、確定済みも下書きも変わらない（D-74）。変えないのは献立に写した値（人数・おやつを出す曜日の日・週の予算）で、重複の期間（FR-COND-05）と補足ルール（FR-COND-06）は、献立を作る・直すときの今の設定を使う。ただし避ける品目・探す言葉・再確認期間はアレルゲンの判定に使うため、変更はすぐに今日以降の献立の警告に反映する（[03 の 5](03-allergen-safety.md#5-判定ロジックbiz-に置きxunit-でテストする)）

### 週の予算の扱い

予算は**週ごと**に持つ（2026-11-03 に月単位から変更。月の予算・月の実績は持たない）。表示は **実績 / 予算** の形にする（例：`12,380円 / 12,500円`）。

```
週の予算 = その献立の weekly_budget（作るときに既定の週の予算を写し、職員が上書きできる）
週の実績 = その週の献立の金額の合計
```

- 週は月曜始まりとし、日付は日本時間で判定する（[NFR-OPS-07](06-non-functional.md#4-信頼性運用nfr-ops)）
- 特定の日を豪華にする（誕生日会など）ことは許す。**週の実績が予算を超える場合は警告する**（確定は止めない）
- **店で買うおやつ（誕生日会のケーキ・アイス、パン屋のパンなど）はアプリで扱わない**。その日は日の種類を「おやつなし」にして見出し（例：「誕生日会（ケーキ）」）を付け、その代金の分だけ週の予算を手で下げる（[Q-21](07-open-questions.md)）
- 予算が余ったとき・足りないときの調整は、職員の判断に任せる（1日あたりの目安額などは出さない）

## 2. 避ける品目（アレルギー）の設定（FR-AVOID）

優先度：**必須**

**子どもは登録しない**（名前・呼び名・番号のいずれも保存しない）。全員が同じおやつを食べるため、施設として「避ける品目」の一覧を1つだけ持つ。

| ID | 要件 |
| --- | --- |
| FR-AVOID-01 | 施設の「避ける品目」を、「29品目」と「施設で追加した品目」（ヘーゼルナッツなど）から複数選んで設定できる |
| FR-AVOID-02 | 「ナッツ類（すべて）」などのグループを選ぶと、含まれる品目をまとめて選べる（そのあと個別に外せる。[03 の 2.3](03-allergen-safety.md#23-グループ)） |
| FR-AVOID-03 | 選びたい品目がマスタにない場合、その場で施設の追加品目として登録できる（品目名と「原材料名で探す言葉」） |
| FR-AVOID-04 | （欠番。29品目以外に避けているものは特にないため、注意メモは作らない。[Q-12](07-open-questions.md)） |
| FR-AVOID-05 | 避ける品目を外すときは、確認のダイアログを出す（「この品目を避ける子がもういないことを確認しましたか？」） |
| FR-AVOID-06 | 避ける品目の追加・削除と、探す言葉の追加・削除は、日時・操作した職員・内容を記録する（`safety_setting_logs`） |
| FR-AVOID-07 | 施設の追加品目の「探す言葉」を追加・削除できる。探す言葉を消すと見落としが増えるため、削除には確認のダイアログを出す。最初から入っている言葉（初期データ）は削除できない。施設の追加品目は、避ける品目・グループ・アレルゲン確認の記録のどれからも使われていなければ削除できる（D-56） |
| FR-AVOID-08 | 法令の29品目は、品目の追加・削除・名前の変更を画面からはできない（制度の変更はマスタデータの更新で行う）。探す言葉の追加はできる。削除できるのは施設が足した言葉だけで、最初から入っている言葉（初期データ）は削除できない（D-50） |

### 受け入れ条件

- 子どもに関する情報（名前・呼び名・番号・人数の内訳）を入力・保存する欄を作らない
- 避けたい食材は、できるだけ自由記述ではなく品目として登録する（品目にすれば、原材料の全文からアプリが自動で探せるため）

## 3. チラシ取り込み（FR-FLYER）

優先度：**必須**

チラシを撮影するか、画像・PDF のファイルで取り込み、載っている商品と価格を取り込む。

| ID | 要件 |
| --- | --- |
| FR-FLYER-01 | チラシを次のどちらでも取り込める（複数枚・複数ファイル可）<br>・**写真撮影**：スマホのカメラを直接起動して撮る。「小さい文字が読めるよう、1ページを半分ずつ近づけて撮る」ことを案内する<br>・**ファイルのアップロード**：画像（JPEG・PNG・HEIC）または PDF を選ぶ。PC ではドラッグ＆ドロップでも追加できる<br>・1回に取り込めるのは10枚（PDF はページ）まで。1ファイル 20MB まで（[NFR-UX-02a](06-non-functional.md#3-使いやすさnfr-ux)） |
| FR-FLYER-01a | PDF は1ページずつ読み取る。ページ数が多い場合は、取り込むページを選べる |
| FR-FLYER-01b | 取り込んだ画像・ページは、抽出の前にサムネイルで一覧表示し、不要なものを外したり追加したりできる |
| FR-FLYER-02 | チラシは**献立作成の最初の手順**として取り込む。対象週は献立で選んだ週を使う。現場では**再来週分を注文する**ため、今週届いたチラシは再来週の献立で取り込む（[Q-19](07-open-questions.md)）。その献立に掲載品の写し（FR-FLYER-07）があれば取り込み済みとして、この手順を飛ばせる（取り込み直すこともできる）。取り込み直したときは、その結果を最初に確定した時点で前の写しを空にし、そこから確定のたびに追記する。取り込み直しを途中でやめたら、前の写しのまま。取り込み直して掲載品から消えた商品は、献立からは消さず、エラー「その週の掲載品にない」として示す（D-47）。献立は過去の週も作れるため、過去の週のチラシも取り込める |
| FR-FLYER-03 | Claude が画像から商品名・メーカー・内容量・価格・注文番号・対象年齢の表示・アレルゲンマーク（あれば）・説明文を抽出する。説明文は、避ける品目の「探す言葉」を探すためだけに使い、保存しない（[03 の 3](03-allergen-safety.md#3-ステータス)） |
| FR-FLYER-03b | 価格は税込を使う。チラシには「税抜価格（税込価格）」の形で両方載っているため、括弧内の税込価格を読む。税込が読めない場合は職員に入力を求める |
| FR-FLYER-03c | 内容量の表記（例：「40g（2袋×12個包装）」「4g×3袋」「100ml×18」）から、Claude が **入数（1パックで何人分か）の候補** を理由つきで出す。職員が確定する（個包装の数と袋の数のどちらを1人分とみなすかは商品による） |
| FR-FLYER-03d | 「箱で」「1個当たり○円」のようなまとめ買いの表示は、まとめ買いの単位と価格をそのまま読み取る |
| FR-FLYER-03a | Claude が商品ごとに **タグ** の候補を付ける：パッケージや商品名に描かれた**キャラクター**（例：商品名やパッケージ写真から読み取れるもの）、**味・種類**（決まった語から選ぶ：スナック・せんべい・焼き菓子・チョコ・キャンディ・グミ・ゼリー・プリン・アイス・ジュース・牛乳・お茶・パン・果物。仮の語で、実際のチラシと試用で見直す。D-61）。職員は修正できる。しょっぱいもの・あまいものなどは、タグではなく「おやつの分類」（FR-FLYER-03e）で表す |
| FR-FLYER-03e | Claude が商品ごとに **おやつの分類** の候補を付ける：しょっぱいもの / あまいもの / デザート・飲料（ゼリー・ジュースなど）/ 対象外。職員が確定する。分類は重複ルール（FR-COND-05）と献立の組み合わせに使う |
| FR-FLYER-03f | 抽出結果を、アプリ（Biz）で次の点から確かめる（Claude は呼ばない）<br>・税抜と税込の整合（税込が税抜×1.08 または ×1.10 を切り捨て・四捨五入・切り上げしたもののどれかに合えば整合とする。D-59）<br>・必須の項目（商品名・内容量・税込価格）の抜け<br>・同じチラシの中での二重の読み取り（正規化した商品名・内容量が同じ）<br>・内容量の表記から入数の候補が出せるか |
| FR-FLYER-03g | 読み取りとは別の呼び出しで、Claude にチラシの画像と抽出結果を渡し、**読み違いを探させる**（価格・商品名・内容量の読み違い、読み落とした商品、読み落としたアレルゲン表記）。出力は「疑わしい箇所と理由」だけとし、**抽出結果を書き換えさせない**。直すのは職員（[SR-19](03-allergen-safety.md)） |
| FR-FLYER-03h | FR-FLYER-03f・03g で見つかった点は、抽出結果の一覧で該当する商品・項目に印と理由を付けて示す。読み落としの指摘は、手入力で追加できる候補として示す |
| FR-FLYER-04 | 抽出結果を一覧で表示し、職員が修正・削除・おやつ対象外の指定をできる |
| FR-FLYER-04a | 一覧では、商品ごとに読み取ったアレルゲン表記（例：「乳・小麦」）と、表記が「なし」と読まれたことを明示する。「なし」は読み落としの可能性があるため、職員がチラシと見比べられるようにする |
| FR-FLYER-05 | 抽出した商品ごとに、既存の商品マスタとの照合結果を表示する（照合の手順は 3.1） |
| FR-FLYER-06 | 職員が照合結果を確定する：「既存の商品と同じ」「味違い・内容量違いとして登録」「新しい商品として登録」「取り込まない」のどれか。味違い・内容量違いは別の商品として登録し、アレルゲン確認を引き継がない（[SR-05](03-allergen-safety.md)）。「取り込まない」は食品以外など、おやつに使わない掲載品に使う |
| FR-FLYER-06a | 照合が「同じ商品」（完全一致）の商品は、まとめて確定できる。完全一致でない商品の選択の既定は「新しい商品として登録」とする（迷う場合は別商品） |

| FR-FLYER-08 | サーバーは、読み取りと読み取りの検証（FR-FLYER-03g）の Claude の呼び出しが終わったら、すぐに画像を破棄する（保存しない）。検証は画像を破棄する前に、同じ処理の中で行う。抽出結果の一覧で画像を見比べるときは、ブラウザが持っている画像を使う |

### 3.1 商品の照合

1. **正規化**：保存時と検索時に同じ関数を使う（NFKC → カタカナをひらがなに → 「CO・OP」「コープ」の除去 → 記号・空白の除去）
2. **完全一致**：正規化名と内容量（表記をそろえたもの）が一致すれば（メーカーは両方に値があるときだけ比べる。チラシではメーカーが空のことが多いため）「前回と同じ商品」の候補にする。正規化名が同じで内容量が違えば「内容量違い」の候補にする。ここで決まったものは Claude を呼ばない
3. **候補検索**：2 で決まらない商品は、文字バイグラムの Dice 係数で上位5件を出す（しきい値 0.3。実際のチラシで精度を測り、必要なら設定で変える）
4. **Claude の判定**：候補が出た商品（似ているが一致しない、迷うもの）だけを、1商品につき1回（候補5件をまとめて）Haiku に渡し、候補ごとに「同じ商品 / 味違い / 内容量違い / 別商品」を判定させ、理由を添える。1回の取り込みでの呼び出しの数には上限を設ける（設定で変える）。上限を超えた分・失敗した分は、判定なしで候補だけを示す（D-63）
5. **職員が確定**：迷う場合は「別商品」として扱う（確認する側に倒す）

- 形態素解析・ベクトル検索は使わない（数百件の規模なので、全件の計算で足りる）

### 受け入れ条件

- 抽出に失敗した場合でも、手入力で商品を追加できる（抽出結果の一覧からも、抽出結果がないときからも始められる）。取り込みの画面で手入力した商品は、職員がチラシを見て入れたものとして、チラシから読み取った商品と同じ扱い（「参考」）にし、同じ照合（3.1）と同じ選択肢（FR-FLYER-06）にかける（D-73）
- 読み取りの検証（FR-FLYER-03g）が失敗した場合でも、抽出結果は表示する。そのとき「読み取りの検証ができなかった」ことを示す
- 税込と税抜の整合チェック・二重の読み取りのチェックには xUnit のテストがある
- 照合結果が「味違い」の商品は、元の商品のアレルゲン確認を引き継がない（[SR-05](03-allergen-safety.md)）
- チラシのアレルゲン表記（説明文の末尾の「（乳・小麦）」など）から得た情報は、ステータス「参考」として、書かれている品目を「含む」として記録する。推奨20品目・経過措置中のカシューナッツなども、表記に書かれていれば「含む」とする。説明文で避ける品目の「探す言葉」が当たった品目も「含む」に入れる（[03 の 3](03-allergen-safety.md#3-ステータス)の「チラシの品目」）。**書かれていない品目を「含まない」とはしない**。チラシの表記は表示義務のある特定原材料（9品目）が対象とみなすため、推奨20品目・経過措置中のカシューナッツ・施設の追加品目は、表記に書かれていないことからは判断しない
- チラシを取り込んだときに「参考」の記録を追加するかは、[03 の 3](03-allergen-safety.md#3-ステータス) の表で決める（記録がない → 追加する / 過去に「確認済み」がある → 追加しない（食い違いは SR-20）/ 「参考」だけ → チラシの品目が増えたときだけ追加する）
- チラシにアレルゲン表記がない商品も、ステータス「参考」（情報源：チラシ、「表記なし」）として記録する。「含む」品目は空で、**どの品目も「含まない」とはしない**。「不明」にすると、避ける品目が設定されている施設では使い始めの週に候補がなくなるため（[SR-09](03-allergen-safety.md)）。献立に使う場合は「参考」と同じく警告を出す
- 正規化・Dice 係数の計算には xUnit のテストがある

### チラシの特徴（実物のチラシで確認したこと）

- 1枚に約20商品。お菓子だけでなく**飲み物**（お茶・水・ジュース・牛乳）も載っている
- 商品ごとに4桁の**注文番号**がある
- 価格は「税抜（税込）」の2つが載っている
- 説明文の末尾に「（乳・小麦）」のような**アレルゲン表記**がある（表示義務のある特定原材料が対象とみなす。調べた時点のチラシは改正前の8品目の可能性がある）
- 「次回予定▶10月2日」のような次回の掲載予定、「値上げ」「箱でお届け」「冷蔵」などの表示がある
- 「○カ月頃から」「1歳頃から」のような**対象年齢**の表示がある（乳幼児向けの商品も混ざる）
- **キャラクター名が商品名に入っている**商品がある。パッケージの絵だけで分かるものもある
- 説明文は小さい文字で、スマホで撮影すると読み取りにくい可能性がある
- **実際に、高解像度の画像でも「(乳)」の表記を読み落とした**（2026-11-02、要件づくりの中で Claude が乳性飲料・牛乳の「(乳)」を見落とした）。チラシからの読み取りは誤りがある前提で扱う

## 5. 献立作成（FR-MENU）

優先度：**必須**

### 5.1 週の要望（自然言語の条件）

固定条件以外の条件は、献立を作るときに職員が文章で伝える。

例：
- 「おやつとして、しょっぱいもの、ゼリー系を合わせて出したい」
- 「金曜日は誕生日会があるので、豪華なおやつにしたい」
- 「水曜日は都民の日なので、子どもが○○人」
- 「木曜は休み」「〇〇は不人気なので使わない」
- 「（キャラクター名）のお菓子を入れたい」

| ID | 要件 |
| --- | --- |
| FR-MENU-01 | 献立を作るとき、その週の要望を自由な文章で入力できる（空欄でもよい） |
| FR-MENU-02 | Claude は要望を読み取り、**構造化できるもの**と**方針として扱うもの**に分ける |
| FR-MENU-02a | 要望の読み取りと献立案の作成は、1回の Claude の呼び出しで行う（D-66）。要望が空欄なら、読み取りを省いて献立案だけを作る。読み取った結果は次の形で受け取る（`interpreted_requests`）：日ごとの値（日付・人数・日の種類・見出し。変えるものだけ）、方針の一覧（文章と、関係する日）、反映しなかった要望の一覧（文章と理由）（D-45） |
| FR-MENU-03 | 構造化できるもの（日ごとの人数の変更、「休み」「おやつなし」などの日の種類、「誕生日会」などの日の見出し）は、アプリの値として反映し、画面に表示する。アレルギー・予算・重複の期間を緩める要望などは反映せず、「反映しなかった要望」として理由とともに警告で示す |
| FR-MENU-04 | 献立案と一緒に「要望をこう理解しました」という一覧を表示し、職員が誤りを直せる（人数・日の種類・日の見出しは画面上で直接修正できる）。「要望を直す」で手順3に戻り、要望を書き直して献立案を作り直せる（作り直す前に、今の案が消えることを確認する）。作り直しても、職員が画面で直した人数・日の種類・見出しはそのまま残す（D-57） |
| FR-MENU-05 | 方針として扱うもの（組み合わせ・豪華にしたい日・避けたい商品など）は、日ごとの理由の中で「どう反映したか」を説明する |
| FR-MENU-06 | 要望は献立ごとに保存し、あとで見返せる |
| FR-MENU-06a | 要望にキャラクター名や味・種類が含まれる場合、商品のタグ（[FR-FLYER-03a](#3-チラシ取り込みfr-flyer)）が一致する商品を優先して選ぶ。一致する商品がチラシにない場合は、そのことを説明する |

#### 要望で変えられないもの

- **アレルギーの条件は、要望の文章では緩められない。** 例えば「卵の子は今日お休み」と書かれても、アプリ側の判定はそのままにし、警告を出す。**出欠は献立に反映しない**（常に施設の避ける品目すべてを条件にする。[Q-13](07-open-questions.md)）
- 週の予算額は要望では変えられない（変えるのは職員が画面で行う）。特定の日に予算を多く使うことはできるが、週の予算を超えれば警告する
- 人数の変更は、要望から読み取った値を画面に表示し、職員の目に触れる形で反映する（金額計算に直結するため）

#### 5.2.1 ツールを使う献立づくり（エージェント）

FR-MENU-16 の作り方。献立案の作成とチャットでの組み直しは、はじめからこの形で作る（D-82。1回の呼び出しの版は作らない）。FR-MENU-15 の検証は `submit_menu` と最後の検証で必ず行い、エラーのある案は受け付けずに Claude に返す（差し戻しの回数は、ループの上限10回の中で数える）。週の要望の読み取り（D-66）も同じループの中で行い、`submit_menu` で読み取り結果と献立案を一緒に出させる。エージェントにするのは献立づくり（献立案の作成・チャットでの組み直し・届いた後の代わりの提案）だけとし、チラシの読み取り・照合の判定・アレルゲン抽出などは1回の呼び出しのままにする。

| ツール | 中身（Biz が計算する） |
| --- | --- |
| `search_products` | 条件（分類・タグなど）でその週の掲載品を探す。**判定が「入れられない」の商品（含む・含む可能性あり・不明）・価格か入数が未入力の商品・「今週は使わない」の商品は、最初から結果に入れない** |
| `check_budget` | 案の合計金額・1人あたり金額・週の予算との差を計算する（[金額計算の定義](#金額計算の定義)） |
| `check_duplicates` | 重複ルール（FR-COND-05）の期間内の商品を返す |
| `validate_menu` | 案全体を FR-MENU-15 と同じ検証にかけ、問題の一覧を返す |
| `submit_menu` | 案を提出する。**FR-MENU-15 の検証に通らなければ受け付けず**、問題をエラーとして Claude に返す |

- Claude はアレルゲンを判定しない。ツールが返す結果だけを使う（[SR-18](03-allergen-safety.md)）
- 献立は `submit_menu` を通らないと確定しない。Claude がツールを使わずに案を返しても、最後の検証は必ず通る。`submit_menu` が受け付けた時点でループを止める
- エージェントは **Claude Managed Agents** で動かす（D-94）。エージェント（モデル・システムプロンプト・上の5つのツール）は `agents/oyatsu-menu-planner/` のファイルに書き、`ant apply` で Anthropic 側に作る。ループと会話の履歴は Anthropic 側が持ち、ツールは**カスタムツール**としてこのサーバー（Biz）が実行する。コンテナは使わないので、環境は外に出られないようにする
- チャットは献立ごとに同じセッションを続ける（前のやりとりを Claude 側が覚えている）。毎回のメッセージには最新の条件と今の献立を入れる（職員が画面で直していることがあるため）。献立案を作り直したとき・チャットの履歴を消したとき・前のセッションが正しく終わっていないとき・避ける品目や候補（確認の記録・掲載品）が変わったとき（前のセッションは古い候補やツールの結果を覚えているため）は、新しいセッションで始め、履歴を最初のメッセージで渡す。使わなくなったセッションは Anthropic 側から消す（作り直し・履歴を消したとき・献立を削除したとき・失敗したとき）。職員に残す返答は、終わったときにイベント一覧から、最後のツールの呼び出しか依頼より後ろの文章だけで作る
- 回数の上限はコードで決める（1回の依頼でモデルの呼び出し12回まで。手書きのループの上限10回と、チャットの説明の1回と、差し戻しの余裕）。上限に達したら、最後に検証を通った案、なければ問題の一覧を警告として表示する。モデルの呼び出しが終わるたびに記録し、1日の金額の上限に数える（[NFR-COST-05](06-non-functional.md)）
- 締切の前に戻せるよう、設定（`Claude:MenuPlannerEngine`）で Messages API の上の手書きのループ（10回まで。`tool_choice` は `auto`、`submit_menu` に `strict: true`）にも切り替えられる。2つの版で、ツールの定義（名前・説明文・JSON スキーマ）・振り分け・最初のメッセージは同じものを使う
- ツールの判断ロジックは Biz、ツールの定義・振り分け・セッションの扱いは `OyatsuBiyori.Claude` に置く（[NFR-MNT-05](06-non-functional.md#5-保守性nfr-mnt)）

### 5.6 商品が届いてからの確認

新しい商品は、注文して届くまでパッケージを撮れない。そのため、献立を確定する時点では「参考」「不明」の商品が残るのが普通である。届いてからパッケージで確認し、問題があれば献立を直す。

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-MENU-36 | 必須 | アレルゲン確認の記録、または避ける品目・探す言葉の変更の結果、商品の判定が「入れられない」（[03 の 5](03-allergen-safety.md#5-判定ロジックbiz-に置きxunit-でテストする)。含む・含む可能性あり・不明）になった場合、**その商品を使う今日以降の献立（下書き・確定）に警告を出す**。警告は献立一覧の上部と、該当する献立の日ごとのカードに表示する（[SR-17](03-allergen-safety.md)）。警告は保存せず、表示のたびに今日以降の献立の商品と、その時点の判定から求める（避ける品目や探す言葉を増やした場合も同じ警告が出る） |

- 警告は、職員が献立を直す（その商品を外す）か、新しい確認の記録で判定が「入れられない」でなくなるまで消えない

### 受け入れ条件

- **人数・金額・週の予算・アレルゲンの判定は、Claude の出力を信用せず、アプリ側のロジック（Biz）で計算する**。Claude は案・理由・要望の読み取りを担う
- 要望から読み取った人数の変更は、画面に表示され、職員が修正できる
- 金額計算・週の予算の計算・アレルゲン判定には xUnit のテストがある
- Claude が存在しない商品や、チラシに載っていない商品、候補から外した商品を返した場合は、その商品を採用せずエラーとして扱う
- 献立案の作成中は進捗を表示し、失敗したら再試行できる。作成中に画面を閉じても、サーバーで続ける（[NFR-PERF-05](06-non-functional.md#2-性能nfr-perf)）

### 金額計算の定義

```
必要パック数の既定 = 切り上げ（その日の人数 × 1人あたりの個数 ÷ 入数）
商品の金額         = 必要パック数（保存した値） × 税込価格
その日の金額       = その日の商品の金額の合計
1人あたり金額      = その日の金額 ÷ その日の人数
```

- 必要パック数は保存する値とする。既定は上の式で求め、入れ替え案と職員の操作で上書きできる。その日の人数か1人あたりの個数を変えたら、式で求め直す。「その日の人数 × 1人あたりの個数」に足りないパック数なら警告する（FR-MENU-08a）
- 「1人あたりの個数」は商品ごとに既定値を持ち（`default_per_child_count`、既定1）、献立に入れるときに写す。献立の中で個別に変えられる
- 入数・1人あたりの個数は1以上の整数、税込価格は1以上の整数とする（0で割らないため）。日ごとの人数は0以上の整数とする
- 税込価格と入数は、**注文できる単位1つあたり**とする（「箱で」のまとめ買いは、1箱の価格と1箱の入数）
- 端数の扱い（1人あたり金額の円未満）は表示時に四捨五入する（計算は小数のまま）
- 日の種類が「おやつなし」の日、人数が0の日は、その日の金額を0とし、1人あたり金額は「—」と表示する（0で割らない）
- 「おやつなし」の日に商品が残っていても、金額は0のままとし、「金額に含まれていません」と警告する（D-77）

- 出力は JSON など構造化した形で受け取り、アプリ側で検証してから使う
- 要望の読み取りと献立の提案は、別々に呼ばず1回の呼び出しにまとめる（D-66）
- 照合は、ルールで決められるもの（完全一致・内容量違い）はアプリが決め、迷うものだけを Claude に判定させる（D-63）
- **モデルは用途ごとに選ぶ**。照合の判定は、ルールで決まらない商品ごとに呼ぶため回数が多くなりうるうえ、最後は職員が確定するため、速くて安い Haiku にする。画像の読み取りと献立づくりは精度を優先して Sonnet にし、読み取りの検証は読み取りと同じ Sonnet で「誤りを探す役」として別に呼ぶ（見落としが多ければ Opus を試す）。献立が要望に合わない場合だけ Opus を試す。モデル名は用途ごとに設定から読む（[NFR-OPS-05](06-non-functional.md)）
- タイムアウトは、画像の読み取りと献立づくりが90秒、照合の判定が30秒。失敗したら2回まで再試行する（[NFR-OPS-04](06-non-functional.md)）。1日の上限は、使った金額（ドル）で決める（D-95。[NFR-COST-05](06-non-functional.md)）
- アレルギーの条件は「施設の避ける品目の一覧」として送る（子どもの情報はそもそも持たない。[NFR-SEC](06-non-functional.md)）
- 画像・要望・チャットの文章は「データ」として渡し、その中の指示には従わせない。Claude の出力を、アレルゲンの判定・ステータス・設定の更新に使わない（[NFR-SEC-11](06-non-functional.md)）
