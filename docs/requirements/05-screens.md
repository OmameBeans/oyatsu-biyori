## 3. 主な画面の内容

### SC-13 ランディング

ルート（`/`）に表示する。ログインしなくても見られる。**実データを出さない**（FR-LP-01）。上から次の順に並べる。

1. **ファーストビュー**：アプリ名・一言の説明・「ログイン」ボタン・献立案の画面の画像。ボタンはログインしていてもいなくても「ログイン」とし、ランディングではログインの状態を確かめない（API を呼ばない）。ログイン済みなら、ログイン画面（SC-01）から献立一覧へ移る（[07 の D-69](07-open-questions.md)）
2. **こんな悩みはありませんか**：毎週1〜2時間・条件が多い・気が抜けない（FR-LP-03）
3. **使い方**：撮る → 確かめる → 伝える → 直す の4ステップを、画面の画像つきで（FR-LP-04）
4. **できること**：理由つきの提案・文章で伝える要望・予算に合わせる入れ替え案・重複の警告（FR-LP-05）
5. **安全への考え方**：アプリが必ずチェックすること / 職員が確定すること / 3つの表示（🔴 使えません・🟡 要確認・🟢 使えます） / 29品目外の食材（FR-LP-06）。色を変えた区画にして、ほかの区画より目立たせる
6. **デモ動画**（あると良い。FR-LP-08）
7. **作った理由**：開発の背景（FR-LP-09）
8. **フッター**：ハッカソン名・GitHub・Claude の表記（FR-LP-10）

- 画面の画像は、ダミーデータを入れた環境で撮る（FR-LP-07）
- やわらかい雰囲気にする（「おやつ日和」の名前に合わせ、明るい色・丸みのある形）。ただし安全の区画は落ち着いた色で、きちんと読ませる

### SC-01 ログイン

- ログイン名とパスワードを入れてログインする。成功したら献立一覧（SC-10）へ移る
- ログイン済みの状態でこの画面を開いたら、すぐに献立一覧へ移る（D-69）
- 初期パスワードのままなら、パスワード変更（SC-12）へ移る（FR-AUTH-03b）

### SC-02 ホーム（左サイドバーの枠）

- ログイン後のすべての画面の枠。左のサイドバーで「献立一覧」「商品一覧」「設定」を選ぶ。ログアウトもここに置く
- ホーム専用の中身は持たない。ログイン直後は献立一覧（SC-10）を表示する
- PC ではサイドバーを常に表示し、上部のボタンで開閉できる。閉じるとアイコンだけの細い帯になり、そこからも各画面へ移れる。開閉の状態はブラウザに保存する。スマホでは折りたたみ、≡ ボタンで開く

### SC-10 献立一覧

- 上部に、必要なときだけ注意を出す（何もなければ出さない）。「パッケージで確認する商品」は、🟡 要確認の商品と、情報がないため 🔴 使えませんになっている商品のこと（03 の 6.3）
  - **「今日以降の献立で使う、パッケージで確認する商品が n件あります」**（下書き・確定の献立に入っている商品。「使わない」にした商品も数える）。確定のときに「届いたら確認する」とした商品を、届いたあとに見落とさないため。「商品を確認する」で商品一覧（SC-06）をその絞り込みで開く
  - そのほかの、パッケージで確認する商品（献立で使っていない商品）と未確定の献立の件数は出さない。前者は商品一覧の絞り込み、後者は週ごとの一覧の状態で分かる
- 届いた商品の確認で 🔴 使えませんになった商品を使う献立があれば、ほかの表示より目立つ形で最上部に出す（例：「11/12（水）の献立に、避ける品目（卵）を含む商品があります」）。そこから献立を開ける（FR-MENU-36）
- 週ごとの一覧：対象週・状態（未作成 / 下書き / 確定）・「週の実績 / 週の予算」（超えたら、超えた額）・警告のバッジ（「🔴 使えません 1件」「🟡 要確認 3件」「確認し直し 2件」。FR-MENU-34a。同じ商品を2つのバッジに重ねて数えない：確定済みの献立で今の判定に対して確認が済んでいない 🟡 の商品は「確認し直し」、それ以外の 🟡 の商品は「要確認」。D-90）・週のメモ（あると良い）。今週・来週・再来週は、未作成でも行を出す
  - 献立一覧には「今週とこれから」（今週以降の週）だけを出す。今週を一番上にして枠で目立たせ、古い順（来週・再来週…）に並べる。最後に「さらに先の週の献立を作る」を置く
  - 今週より前の週は「過去の献立」（SC-14）で見る。一覧の下に「過去の献立を見る（n週）」を置く（過去の週がなければ出さない）
- 下書きは、行のメニューから削除できる（確認のダイアログあり。FR-MENU-31a）
- 未作成の週は「献立を作る」、下書き・確定の週は「開く」で SC-09 へ進む
- 「週を選んで献立を作る」（日付を選んで、一覧に出ていない週の献立を作る入口）は置かない（D-88 で取りやめ。D-49）。今週より先の週は「さらに先の週の献立を作る」で作る
- PC では、上部の注意・見出し・「さらに先の週の献立を作る」・「過去の献立を見る」を固定し、週のカードの部分だけをスクロールする
- 「確認し直し」のバッジは、献立のカードで警告の商品にチェックを付け直すと消える。献立は確定のまま（D-71）
- 印刷（FR-LIST-04）・商品名での検索（FR-LIST-02）はあると良い

### SC-14 過去の献立

- 献立一覧（SC-10）の「過去の献立を見る」から開く（`/menus/history`）。サイドバーの項目は増やさない（「献立一覧」を選んだ状態のまま）。「献立一覧へ戻る」で戻る
- 今週より前の週を新しい順に出す。項目は SC-10 の週ごとの一覧と同じ（対象週・状態・「週の実績 / 週の予算」と差額・警告のバッジ）
- PC は表（MUI X の DataGrid）で、画面の高さいっぱいに出し、表の中だけをスクロールする。🔴 の商品がある週は行に色を付ける（バッジの文言もある）。スマホはカードで出す
- 「開く」で SC-09 へ進む。下書きは行のメニューから削除できる（FR-MENU-31a）
- 過去の献立の中身の表示（FR-LIST-01）・商品名での検索（FR-LIST-02）・印刷（FR-LIST-04）は、この画面に足す（あると良い）

### SC-09 献立作成

献立一覧（SC-10）の「献立を作る」「開く」から入る。チラシの取り込みから献立の確定までを、1つの画面で4つの手順に分けて進める（画面上部に手順を表示し、終わった手順には戻れる）。
SC-05（チラシ取り込み）は、この画面の手順1にまとめたため欠番とする。

- 途中でやめても、それまでの内容（確定した商品・今週は使わない指定・要望・献立案）は下書きとして保存され、再開できる。撮影はスマホ、献立案は PC のように、途中で端末を変えて続けられる。確定前の読み取り結果は、サーバーのメモリに24時間だけ残る（再起動したら読み取り直し。FR-FLYER-10）

#### 手順1：チラシ取り込み

その週のチラシを取り込み済みなら飛ばして手順2から始める。手順2から「チラシを取り込み直す」で戻れる。

1. チラシを取り込む（複数枚可）。対象週は献立で選んだ週を使う
   - 「カメラで撮る」「ファイルを選ぶ」の2つのボタンを並べる。PC では画面にファイルをドラッグ＆ドロップしても追加できる
   - 撮影の前に「小さい文字が読めるよう、1ページを半分ずつ近づけて撮ってください」と案内する
   - PDF はページをサムネイルで並べ、取り込むページを選ぶ（FR-FLYER-01a）
   - 取り込んだ画像・PDF のページをサムネイルで並べ、不要なものを外してから「読み取る」を押す（10枚まで）
2. 抽出中の進捗を表示する。画面を閉じても読み取りは続き、戻ると結果が出る（FR-FLYER-10）
3. 抽出結果の一覧：商品ごとに次を表示し、職員が確定する
   - 照合結果（同じ商品 / 味違い / 内容量違い / 新規）と理由。確定の選択肢は「同じ商品」「味違い・内容量違いとして登録」「新しい商品として登録」「取り込まない」（FR-FLYER-06）
   - 読み取った商品名・内容量・税込価格・注文番号・入数の候補と理由・おやつの分類・タグ。どれも直せる
   - 読み取ったアレルゲン表記（「乳・小麦」）、または「表記なし」と読まれたこと（FR-FLYER-04a）
   - 読み取りの検証で疑わしい項目の印と理由（FR-FLYER-03h）。検証ができなかった場合はその旨
   - 「確認済み」の商品で、チラシの表記と食い違う場合はその内容と選択肢（FR-FLYER-09・SR-20）
   - 確定した商品は「確定済み」の印を付けて一覧に残し、選び直せる（D-53）
   - 一覧は表（MUI X の DataGrid。列：開閉・状態・商品名・アレルゲン表記・同じ商品か。スマホでもアレルゲン表記が横にスクロールせずに見えるよう、商品名のすぐ右に置く）。状態は「警告あり（食い違い・説明文の避ける品目の言葉・品目に当てはめられない語・検証の指摘）/ 要確認（同じ商品かどうかが決まっていない・表記なし）/ 未確定 / 確定済み」で、この順に並べる（確定済みは必ず下。列での並べ替えはしない）。表の上のタブで状態ごとに絞り込める
   - 状態のチップの下に、何を確かめるのかを短く添える（「表記なし」「同じ商品か選ぶ」など。アレルゲンに関わるものを先に並べ、確定済みの行にも出す）。アレルゲン表記の列には、読み取った表記の原文と、品目・表記なし・説明文の避ける品目の言葉・パッケージでの確認との食い違い（避ける品目なら error の色）のチップを出す
   - 表の上の「未確定を1件ずつ確かめる」で、未確定の商品を1件ずつダイアログで確かめられる（前へ・あとで・確定。決めるのはボタンを押したときだけ）
   - 確定のフォームは、直してほしい欄（指摘がある・読み取れず空）だけを出し、ほかの欄は1行の要約にまとめて「ほかの項目も直す」で開く。アレルゲン表記と、品目の分からない語の欄はいつも出す
   - 確定の操作は、行の下に開く詳細欄で行う。詳細欄の先頭に「確かめること」（理由ごとに、どこを見て何を選ぶ・直すか）を出し、検証の指摘は当てはまる入力欄のそばに出す。初めはどの行も閉じておき、確定したら次の未確定の行を開く。スマホでは表を横にスクロールでき、詳細欄は画面の幅に収める
4. 一覧の上部に「『同じ商品』をまとめて確定」ボタンと、確定していない件数（「確定していない12件は今週の商品に入りません」）を出す
5. 読み落としの指摘と、手入力で商品を追加する入口を一覧の下に置く

#### 手順2：今週の商品

今週のチラシに載った商品を一覧で表示する。Claude に献立を作らせる前に、候補とアレルゲンの表示を職員が見渡せるようにする。

- 商品ごとに、商品名・価格・おやつの分類・タグ・アレルゲンの表示（🔴 使えません / 🟡 要確認 / 🟢 使えます）と理由を表示する（[03 の 6](03-allergen-safety.md#6-画面での表示)。例：「🔴 使えません：卵を含みます」「🟡 要確認：チラシにアレルゲンの表記がありません」）
- 避ける品目が1つも設定されていなければ、一覧の上部に「避ける品目が設定されていません」と表示し、設定（SC-04）へ進めるようにする（03 の 6.3）
- 重複ルールの期間内の商品は「○日前に出した」と表示する
- 避ける品目に「表示が確実でない」品目があるときは、「メーカーへの確認が必要」を小さく添える（SR-06）
- 税込価格か入数が未入力の商品は「入数を入れてください」と表示し、その場で入力できる（FR-MENU-07c）
- 🟡・🔴 の商品から、その場でアレルゲン確認（SC-08）へ進める
- 商品ごとに「今週は使わない」を指定できる
- アレルゲンの表示（すべて / 🟡 要確認 / 🔴 使えません）とおやつの分類で絞り込める
- 一覧の上部に件数のまとめを表示する（例：「献立に入れられる商品 15件（うち 🟡 要確認 4件）／ 🔴 使えません 2件」。🟢 の「使えます」と混ざらないよう、「使える」とは書かない）

#### 手順3：要望の入力

1. その週の要望を文章で入力し、「献立を作る」を押す（空欄でもよい）。入力欄には例文を薄く表示する
   - 例：「しょっぱいものとゼリー系を合わせて出したい」「金曜は誕生日会なので豪華に」「水曜は都民の日なので子どもが○○人」
   - 入力欄の近くに「子どもの名前は書かないでください」と、「要望の文章では、避ける品目（アレルギー）の条件は変えられません」を表示する
   - 横に「いつもの条件」（人数・週の予算・避ける品目・重複ルール）を読むだけで表示し、「変更」で設定へ移れる。1日あたりの目安額は出さない（Q-14）
   - （あると良い）よく使う要望を、押すと入力欄に入るボタンとして並べる
2. 「自分で組む（AI を使わない）」を選ぶと、日ごとの枠だけの献立を作り、手順4で手動で商品を入れる（FR-MENU-07d）

#### 手順4：献立案とチャット

- 上部に「要望をこう理解しました」の一覧（例：「水曜：人数 ○○人」「金曜：豪華にする」「毎日：しょっぱいもの＋ゼリー系」）。人数・日の種類・日の見出しはその場で修正できる。「要望を直す」で手順3に戻れる（FR-MENU-04）
- 上部に、3列にまたがるコマンドバーを置く：献立の状態（下書き / 確定済み）・「週の実績 / 週の予算」（予算はその場で上書きできる）・「予算に合わせる」「要望を直す」「確定」。スマホでもどのタブからも見える
- PC（広い画面）では、コマンドバーの下に左から「使える商品」（献立に入れられる今週の商品）・献立（日ごと）・チャットの3列を並べる。列の境目（スプリッター）をドラッグして、左右の列の幅を変えられる（キーボードの ← → でも動かせる。変えた幅はその端末に残る）。狭い画面とスマホではタブ（使える商品 / 献立 / チャット）で切り替える
- 使える商品を日のカードへドラッグすると、その日に足せる。日のカードの商品をほかの日のカードへドラッグすると、その日へ動かす（1人あたりの個数と価格はそのまま、パック数は動かした先の人数で求め直し、確定時の確認は消す）。使える商品の一覧へドラッグして戻すと外せる。ドラッグできない端末（スマホ）のために、使える商品の「＋」から日を選んで足すこともできる（FR-MENU-24）
- 献立案の作成中は、進捗を段階で示す（例：「要望を読み取って、献立を考えています」→「条件を確かめて、直しています」。要望の読み取りと献立の提案は1回の呼び出し（D-66））。
- 日ごとのカード：日の見出し（「誕生日会」など）・商品・1人あたりの個数・パック数・金額・1人あたり金額（円未満は四捨五入）・理由・警告
- カードで、商品の入れ替え・追加・削除、1人あたりの個数とパック数の変更、日の種類（画面の表記は「種別」。通常 / おやつなし。D-92）の切り替えができる（FR-MENU-24）。パック数は人数と個数から求めた値が入り、職員が上書きできる。人数か1人あたりの個数を変えると、求め直す（D-43）
- 避ける品目が1つも設定されていなければ、上部に「避ける品目が設定されていません」と表示する（03 の 6.3）
- 警告は種類ごとに分けて示す：🔴 使えません の商品（赤）・🟡 要確認 の商品（黄）。どちらも理由を添える（03 の 6.2）・「○日前に出した」（重複）・直しきれなかった検証の問題・パック数が全員分に足りない（D-43）・通常の日に商品がない・「おやつなし」の日に商品がある（D-75）。「おやつなし」の日の商品は金額を0のままにし、「金額に含まれていません」と示す（D-77）
- 週の予算を超えたら、予算の表示の横に警告を出す
- 作成に失敗したときは、理由と「もう一度作る」ボタンを出す（入力した要望は残す）
- 届いた後の確認で 🔴 使えませんになった商品がある日は、カードに警告を出す（例：「🔴 使えません：卵を含みます。別の商品に替えてください」）。代わりの提案（あると良い。FR-MENU-38）があれば、カードから選べる
- 「週の実績 / 週の予算」を常に表示し、週の予算はその場で上書きできる（例：金曜は店で買うケーキなので、その分を下げる）
- 「週の実績」が週の予算に届かないときだけ「予算に合わせる」ボタンを出す（予算ちょうど・超えているときは出さない。[07 の D-67](07-open-questions.md)）。押すと入れ替え案（例：「水曜の〇〇を△△に → 週の予算ちょうど」「火曜に□□を追加」）を最大3件、Claude の説明つきで表示する。選ぶと反映する（FR-MENU-28・30）
- 商品ごとにおやつの分類（しょっぱい / あまい / デザート・飲料）を表示する
- 商品のタグ（キャラクター・味）を小さく表示し、要望との対応が分かるようにする
- 警告のある商品から、その場でアレルゲン確認（SC-08）へ進める
- 「下書き保存」「確定」ボタン。確定時は確認のダイアログを出す（FR-MENU-32）
  - エラー（🔴 使えません の商品・価格か入数が未入力の商品・その週の掲載品にない商品）があれば、その一覧を示し「確定する」は押せない（[07 の D-78](07-open-questions.md)）
  - 🟡 要確認 の商品は1件ずつチェックを付ける。すべてに付けると「確定する」が押せる。チェックの文言は、次にすることを含めた1文にする（例：「☐ フルーツゼリー（11/12 水）：届いたらパッケージで確認します」。03 の 6.3）
  - 避ける品目に「表示が確実でない」品目があるときは、ダイアログの末尾に「メーカーへの確認が必要」の1行を必ず出す（03 の 6.3）
  - 候補から外した商品（「今週は使わない」にした商品など）は、確定では警告として示す（確定は止めない。D-78）。通常の日に商品がない日、「おやつなし」の日に商品がある日も警告として示すだけで、確定は止めない（D-75）
- 確定済みの献立を開いたときは、確定済みであることを示す。商品・個数・日の種類などを直し始めたら下書きに戻り、もう一度「確定」を押す（確定時と同じチェックをやり直す。[07 の D-54](07-open-questions.md)）。警告の商品にチェックを付け直すだけなら、確定のまま（「確認し直し」。D-71）

### SC-08 アレルゲン確認

1. パッケージの原材料表示を撮影（または画像ファイルを選ぶ。4枚まで）
2. 撮った画像と、読み取った原材料テキストを並べて表示する。テキストは職員が直せる。読み取れなかった場合や Claude が使えない場合は、テキストを手で入力できる（FR-PROD-05a）。テキストが空のあいだは、情報源がパッケージの記録ボタン（手順5）を押せない（SR-12）
3. 29品目の判定候補（含む / 含まない）を並べて表示
   - 施設が避けている追加品目（ヘーゼルナッツなど）も判定対象に並べる
   - 原材料テキストのうち「探す言葉」に当たった部分を色で強調する（例：「ヘーゼルナッツペースト」）。職員が「含まない」にしても 🔴 使えません の表示は消えないことを、その場で示す（SR-14）
   - Claude が「含む」としなかった品目は未確定のまま並べる。「残りをすべて含まないにする」を職員が押して確定する（自動では確定しない。FR-PROD-06）
   - 「同一工場で製造」などの注意書きを読み取った場合は表示する（SR-11）
   - 避ける品目に「表示が確実でない」品目があれば「メーカーへの確認が必要」を示す（SR-06）
4. 情報源（パッケージ / コープのサイト / チラシ / その他）を選ぶ（既定：パッケージ）。パッケージ以外を選んだときは「パッケージ以外の情報では 🟢 使えます にはなりません（献立では 🟡 要確認 か 🔴 使えません になります）」と示す（FR-PROD-06b。この記録のステータスは「参考」になるが、これは文書のための注記で、画面には「参考」と出さない）
5. 職員が各品目を確認・修正し、記録ボタンを押す（確認者・日時を自動記録）。ボタンの名前は情報源で変える
   - パッケージ：「パッケージで確認して記録」。原材料の全文が空のあいだと、対象品目（29品目と避ける品目にある追加品目）をすべて確定するまで押せない（SR-12・SR-15）
   - それ以外：「パッケージ以外の情報として記録」。「含む」の品目を選んで記録する（すべての品目を確定しなくてよい。FR-PROD-06b）
6. 記録したあとは、記録した結果の表示（🔴 / 🟡 / 🟢 と理由）と、その商品を使う今日以降の献立と日付を一覧で示し、そこから献立を開ける（FR-MENU-37）。記録の結果 🔴 使えませんになった場合は、一覧を目立たせる（例：「11/12（水）の献立に、避ける品目（卵）を含む商品があります」）。使っている献立がなければ、そのことを示す（[07 の D-60](07-open-questions.md)）

### SC-06 商品一覧・SC-07 商品詳細

- 商品一覧：商品名・メーカー・おやつの分類・アレルゲンの表示（🔴 / 🟡 / 🟢 と理由）・最終確認日。検索・アレルゲンの表示での絞り込み（すべて / 🔴 使えません / 🟡 要確認 / 🟢 使えます / パッケージで確認する商品 / 今日以降の献立で使う、パッケージで確認する商品（最後のものは SC-10 の注意から開く））・「使わない」商品の表示の切り替え。避ける品目が1つも設定されていなければ、上部にそのことを表示する（03 の 6.3）
- 商品詳細：基本情報の編集（FR-PROD-04。税抜価格・注文番号・対象年齢・最後に載った週は読むだけ）、タグ（キャラクター / 味・種類を分けて表示）、メモ、「使わない」の切り替え
- 上部に、今のアレルゲンの表示（🔴 / 🟡 / 🟢）と理由・次にすること（03 の 6.2。「要再確認」「未確認の品目あり」の理由もここで示す。SR-16）
- アレルゲン確認の履歴（日時・確認者・情報源・ステータス・含む品目・注意書き）。前回との差（あると良い。FR-PROD-12）。ステータスの名前（確認済み / 参考）を画面に出すのはここだけ（03 の 6.2）
- その商品を使う今日以降の献立（FR-PROD-11）。🔴 使えません の商品では、ここを目立たせる

### SC-03・SC-04・SC-12 設定

- SC-03 条件設定：通常の人数・既定の週の予算・おやつを出す曜日・再確認期間・分類ごとの重複させない期間・重複の補足ルール
- SC-04 避ける品目：グループ（ナッツ類（すべて）・甲殻類）・特定原材料・準ずるもの・施設で追加した品目の順に並べる。品目を外すとき、探す言葉を消すときは確認のダイアログを出す（FR-AVOID-05・07）。施設の追加品目の登録・探す言葉の編集ができる初期データの探す言葉は削除できず、施設が足した言葉だけ削除できる（D-50）。施設の追加品目は、避ける品目に入っておらず、確認の記録などで使われていなければ削除できる（D-56）。施設の追加品目には探す言葉を必ず1つ以上持たせる（登録時に品目名を自動で入れ、最後の1語は削除できない）
- SC-12 パスワード変更：今のパスワード・新しいパスワード（12文字以上）。初期パスワードでログインした直後はこの画面を出す（FR-AUTH-03b）

## 4. UI の方針

- スマホ（縦向き）と PC の両方で使える。撮影する画面・手順（SC-08、SC-09 の手順1）はスマホ優先、献立案（SC-09 の手順4）は PC 優先で設計する
- PC では、画面全体を縦にスクロールさせない。見出し・絞り込み・合計・「保存」「次へ」などのボタンは画面の高さの中に固定し、一覧や明細の部分だけをスクロールする（表の見出しの行も残す）。2列の画面（商品詳細・要望の入力など）は、列ごとにスクロールする。スマホでは、ページ全体をスクロールする（入れ子のスクロールは指で操作しにくいため）
- 文言は日本語で、専門用語を避ける（例：「正規化」「照合」は画面に出さず「同じ商品かどうか」と書く）
- Claude の処理は数十秒〜数分かかることがあるため、進捗を表示し、二重送信を防ぐ
- Claude の出力（理由・説明）は、テキストとして表示する（HTML として描画しない。[NFR-SEC-11](06-non-functional.md)）。チャットの返答だけは、安全な範囲の Markdown で表示し、届いた順に流す（生の HTML・リンク・画像は描画しない。D-91）
- モック（`mocks/`）と要件定義が食い違う場合は、要件定義に従う（食い違いの一覧は [07 の 4](07-open-questions.md#4-モックとのずれ)）
- アレルゲンは、どの画面でも「🔴 使えません / 🟡 要確認 / 🟢 使えます」の3つの表示と、理由・次にすることで示す。色と文字（絵文字かアイコン）の両方で示し、文言はフロントの共通部品だけから出す（[03 の 6](03-allergen-safety.md#6-画面での表示)）
