# 09. チラシ取り込みの分類（D-100）

優先度：**必須**

チラシから読み取った商品を、アプリ（Biz）が **4つの分類**（使えない / 再入力 / 要確認 / 使える）に分け、職員は分類ごとにまとめて片付ける。2026-11-07 に、取り込みの仕様を大きく変えた（[07 の D-100](07-open-questions.md)）。

- この文書は、[02 の 3](02-functional.md#3-チラシ取り込みfr-flyer)（FR-FLYER）・[03 の 2.5](03-allergen-safety.md#25-チラシの表記の略記)・[05 の SC-09 手順1](05-screens.md#手順1チラシ取り込み) のうち、**照合・分類・確定**の部分を置き換える。置き換えるもの・残すものは 8 にまとめた
- この文書と 02・03・05 が食い違うときは、この文書を正とする。ただし 03 の安全要件（SR）の考え方（迷ったら確認する側に倒す・Claude の出力でアレルゲンの判定を緩めない）は変えない

## 1. 変えたことの要点

| これまで | これから |
| --- | --- |
| 似ている商品を文字バイグラムの Dice 係数で探し、Haiku に「同じ商品 / 味違い / 内容量違い / 別商品」を判定させる（D-63） | **似ている商品という考えをなくす**。正規化した「商品名＋メーカー」の完全一致だけで、商品マスタの商品と同じかを決める。Claude は照合に使わない |
| 内容量が違えば「内容量違い」として別の商品にする（SR-05） | 内容量は照合に使わない。名前＋メーカーが同じなら同じ商品で、内容量が変わったら職員が入数を確かめて上書きする |
| 状態は「警告あり / 要確認 / 未確定 / 確定済み」、選択肢は「同じ商品 / 味違い・内容量違い / 新しい商品 / 取り込まない」 | 分類は **使えない / 再入力 / 要確認 / 使える** の4つ（と確定済み・外した掲載品）。職員の選択肢は分類で決まる |
| 略記は6つ（麦・え・か・落・そ・く）。カタカナの「カ」は当てない | 略記に **「カ」＝カシューナッツ** を足して7つにする。「か」（ひらがな）＝かに、「カ」（カタカナ）＝カシューナッツと字で分ける |
| 入数が分からない商品は一覧に入れず、一覧の下に名前だけ出す（D-99） | 「使えない（入数が分からない）」として一覧に出し、入数を入れれば分類し直す |
| 確認済みの商品で、チラシに避ける品目でない品目が増えたら、職員が「確認し直す / チラシの誤り」を選ぶ（SR-20） | 選ばせずに、自動で「参考」の記録を足す（確認する側に倒す） |

## 2. 商品の照合（名前＋メーカーの完全一致）

| ID | 要件 |
| --- | --- |
| FR-IMPORT-01 | 読み取った商品と商品マスタの商品は、**正規化した商品名と正規化したメーカーの両方が一致したときだけ**同じ商品とする。商品名の正規化は今の照合と同じ関数（NFKC → カタカナをひらがなに → 「CO・OP」「コープ」の除去 → 記号・空白の除去）。メーカーは「コープ」を除かない正規化（NFKC → カタカナをひらがなに → 記号・空白の除去。今の照合のメーカーの比べ方と同じ）にする（メーカーが「コープ」だけの商品のメーカーが空にならないように） |
| FR-IMPORT-02 | 内容量・税込価格・注文番号は照合に使わない（内容量が変わっても同じ商品。内容量の変化は 3 の「再入力」で扱う） |
| FR-IMPORT-03 | チラシには**メーカーが必ず載っている**前提とする。メーカーが読めなかった（空の）商品は照合せず、「再入力」にする（メーカーを入れたら照合する）。商品マスタでメーカーが空の商品は、どのチラシの商品とも一致しない |
| FR-IMPORT-04 | 一致する商品がマスタに2件以上あるとき（内容量違いを別の商品として登録していた名残など）は、**最後にチラシに載った週**（`listed_week_start`）がいちばん新しい商品を使う。載った週が同じ・どちらも空のときは、更新日時が新しい商品、それも同じなら ID の順で決める（商品に登録日時の列がないため）。どれを使ったかは一覧に示す |
| FR-IMPORT-05 | 似ている商品の候補（Dice 係数）・Claude（Haiku）による照合の判定・職員が既存の商品を検索して紐づける操作は作らない。一致しない商品は「要確認」になり、新しい商品として登録する |
| FR-IMPORT-06 | 正規化した名前＋メーカーが同じ商品を、1回の取り込みで2回以上読んだとき（半分ずつ撮った写真の重なりなど）は、アプリが自動で1件にまとめる。アレルゲン表記の品目・説明文で当たった探す言葉・品目の分からない語は、両方を合わせる（和集合。確認する側に倒す）。税込価格・税抜価格・内容量・注文番号・入数の候補のどれかが食い違うときは「再入力」にし、食い違った値を両方示す |

- 照合は商品名と内容量の正規化をアプリ（Biz）で行い、Claude は呼ばない。照合の結果は xUnit で確かめる
- 同じ名前・メーカーで大きさ違いの商品が同じチラシに別々に載ったときも、1件にまとめる（内容量・価格・注文番号の食い違いで再入力になる）。商品は名前＋メーカーで1つなので、今週の商品に入れられるのはどちらか1つ。職員は今週使う方の値を選ぶ（注文番号が食い違ったときは、理由の文で大きさ違いの可能性を示す）。注文番号が違ってもまとめない扱いにはしない（分けても同じ商品に一致し、確定で後の行が前の行を上書きするため）。両方を別の商品として扱いたいときは、商品名に大きさを含めて（例：「○○ 大袋」）手入力する。新しい商品になり、「参考」の記録から始まる（アレルゲン確認は引き継がない）
- 照合のたびに、マスタの商品名・メーカーから正規化し直して比べる（数百件なので全件でよい。正規化の関数を直しても保存値とずれない）。`normalized_maker` の列は足さない

## 3. 分類

### 3.1 4つの分類

| 分類 | 意味 | 当てはまる条件 | 職員がすること |
| --- | --- | --- | --- |
| 🔴 **使えない**（赤） | 今週の商品（献立の候補）に入れない | ・入数が特定できない（3.3）<br>・避ける品目が入っている（3.4）<br>・一致した商品を商品一覧で「使わない」（FR-PROD-09）にしている | 何もしなくてよい。読み違いのときは直せる（3.6） |
| 🟠 **再入力**（橙） | 読み取りに足りない・おかしいところがあり、職員が直すまで確定できない | ・税込価格が読めない、または税抜価格と合わない（FR-FLYER-03f の整合）<br>・入数の候補が内容量の表記と合わない（FR-FLYER-03f のアプリの検証の指摘。指摘はどれも再入力）<br>・内容量が読めない<br>・注文番号が読めない<br>・商品名が読めない<br>・メーカーが読めない<br>・アレルゲン表記に、品目にも略記にも当たらない語がある<br>・読み取りの検証（FR-FLYER-03g）の指摘がある<br>・一致した商品と内容量、または入数の候補が違う<br>・二重に読んだ商品で値が食い違う（FR-IMPORT-06）<br>・表記なしと読んだのに、一致した商品の有効な記録では特定原材料を「含む」（読み落としの疑い。D-97 から引き継ぐ） | 理由の欄を直す（または「このままでよい」を押す）。直すと分類し直す |
| 🔵 **要確認**（青。アレルゲンの 🟡 要確認と見分けるため、黄にしない） | 商品マスタに一致する商品がない（新しい商品） | 上のどれにも当たらず、一致する商品がない | 「新しい商品として登録」（1件ずつ、またはまとめて） |
| 🟢 **使える**（緑） | 商品マスタの商品と同じで、避ける品目が入っていない | 上のどれにも当たらず、一致する商品がある | 「使える商品をまとめて確定」（または1件ずつ確定） |

- 取り込みの分類の🟢「使える」は、「職員が商品ごとに選ばなくても今週の商品に入れてよい」という意味で、**アレルゲンの3つの表示（[03 の 6](03-allergen-safety.md#6-画面での表示)）とは別のもの**。一致した商品の記録が「参考」や「要再確認」でも「使える」になり、献立では今までどおり 🟡 要確認として扱う（確定のときの商品ごとの確認も今までどおり。SR-04）
- 分類の名前と色は、献立や商品一覧のアレルゲンの表示と混ざらないよう、取り込みの画面の中だけで使う。画面では「取り込みの分類」と見出しを付け、アレルゲンの表示のアイコンとは別の形（チップ）で出す
- 分類はサーバー（Biz）が決めて API で返し、画面は表示だけにする。確定の API でもサーバーが分類を求め直し、確定できない分類になっていたら確定しない

### 3.2 分類の順番

複数の条件に当てはまるときは、**使えない ＞ 再入力 ＞ 要確認 ＞ 使える** の順で先のものにする。理由は当てはまったものをすべて並べる（例：「税込価格が読めません／卵を含みます」→ 使えない）。

```
取り込みの分類(読み取った商品, 商品マスタ, 避ける品目, 今日):
    一致 = 正規化した商品名とメーカーが同じマスタの商品（2件以上なら FR-IMPORT-04）。
           商品名かメーカーが空なら「なし」
    チラシの品目 = アレルゲン表記の品目（略記の補正後。4）
                 ∪ 説明文で避ける品目の「探す言葉」が当たった品目
    入数 = 読み取りの入数の候補（1以上）、なければ 一致.入数

    使えない の理由:
        入数がない                                               → 入数が分からない
        避ける品目 ∩ チラシの品目 ≠ 空                            → ○○を含みます（チラシの表記・説明文）
        正規化した商品名に、避ける品目の「探す言葉」がある        → 商品名に「○○」があります
        一致があり、一致の判定（03 の 5）が 含む / 含む可能性あり   → 一致の判定の理由（○○を含みます など）
        一致があり、一致.使わない                                 → 「使わない」にした商品です
    使えない の理由があれば → 使えない

    再入力 の理由（3.1 の表の「再入力」の条件。まだ直していない・「このままでよい」を押していないもの）
    再入力 の理由があれば → 再入力

    一致がない → 要確認
    それ以外   → 使える
```

- 一致した商品の判定は、03 の 5 の判定（有効な記録の「含む」・商品名と原材料の全文の探す言葉）を**そのまま使う**。判定が「不明（記録がない）」のときは、今回のチラシの品目で「参考」の記録を足すもの（03 の 3 の表の「記録がない → 追加する」）とみなして分類する（チラシの品目に避ける品目がなければ「使える」。献立では 🟡）
- 「使えない」の理由のうち、入数が分からないこと以外（避ける品目・使わない）は、職員の操作で外せない（SR-10。避ける品目は 3.6 で表記を直したときだけ変わる）
- 避ける品目が1つも設定されていないときは、避ける品目による「使えない」は起きない（03 の 6.3 の「避ける品目が設定されていません」は今までどおり出す）

### 3.3 入数

| ID | 要件 |
| --- | --- |
| FR-IMPORT-10 | おやつは個包装のお菓子だけを出すため、**入数（1パックで何人分か）が特定できない商品は「使えない」**にする。特定できないとは、Claude が内容量の表記から入数の候補を出せず（null か0）、一致した商品にも入数がないこと |
| FR-IMPORT-11 | 「使えない（入数が分からない）」の商品には、行に入数の欄を置く。職員が入数（1以上の整数）を入れると、読み取った内容（アレルゲン表記・説明文を含む。手入力にはしない）のまま分類し直す。入れ直した商品は読み取りの検証を通っていないため、まとめて確定・まとめて新規登録に入れない（1件ずつ確定する。D-99 から引き継ぐ） |
| FR-IMPORT-12 | 一致した商品があり、チラシの内容量（表記をそろえたもの）または入数の候補がマスタと違うときは「再入力」にし、マスタの値とチラシの値を並べて示す。職員が入数を確かめて（直すか「このままでよい」）から分類し直す。確定したら、マスタの内容量・入数をチラシ（直した値）で上書きする（1人あたりの金額が変わるため、黙って上書きしない）。ただし、献立の週がその商品の最後に載った週より前のとき（過去の週の取り込み。FR-FLYER-07 と同じ条件）は、マスタの内容量・入数を上書きしない（古い値に戻さないため）。マスタの内容量か入数が空のときだけ埋める。再入力は過去の週でも出す |

- 内容量が変わっても、名前＋メーカーが同じなら同じ商品として扱い、**アレルゲン確認を引き継ぐ**（D-100 で SR-05 を見直した）。内容量の変わり目でリニューアル（原材料の変更）があることもあるため、FR-IMPORT-12 の再入力の理由に「内容量が変わりました。届いたらパッケージの原材料も見てください」と添える（判定は変えない）

### 3.4 避ける品目が入っているかの判定

次の**どれか1つでも**当たれば「使えない」にする。

1. **チラシのアレルゲン表記**：表記の品目（4 の略記の補正をしたあと）に避ける品目がある
2. **チラシの説明文**：説明文に、避ける品目の「探す言葉」がある（今の「チラシの品目」と同じ。説明文は保存しない）
3. **商品名**：正規化した商品名に、避ける品目の「探す言葉」がある（SR-14）
4. **商品マスタの記録**：一致した商品の判定（03 の 5）が「含む」か「含む可能性あり」（有効な記録の「含む」と、原材料の全文の探す言葉）

- 1・2 は今回のチラシだけで決まるので、マスタに一致がない（新しい）商品にも効く
- 一致した商品が「確認済み」でも、1・2 に当たれば「使えない」にする（チラシが新しい情報かもしれないため。SR-20 の扱いは 3.5）
- 判定はステータスより先に「含む」を見る（03 の 5 と同じ）

### 3.5 確認済みの商品とチラシの表記の食い違い（SR-20 の見直し）

一致した商品が「確認済み」で、チラシの品目に、有効な記録で「含む」になっていない品目があるとき：

| 増えた品目 | 分類 | 記録 |
| --- | --- | --- |
| 避ける品目 | 🔴 使えない | 「参考」の記録（チラシの品目を「含む」）を**自動で**足す |
| 避ける品目でない | 🟢 使える（ほかの条件に当たらなければ） | 「参考」の記録（チラシの品目を「含む」）を**自動で**足す。職員に「確認し直す / チラシの誤り」を選ばせることはやめる |

- 足した記録で、商品一覧・ほかの週の献立でも 🔴（避ける品目）か 🟡（参考）になる。パッケージで確認し直せば（新しい「確認済み」の記録）戻る（03 の 3 の「有効な記録」）
- 記録を足すのは、**その取り込みで最初に確定したとき**（「使える商品をまとめて確定」・「新しい商品をまとめて登録」・1件ずつの確定のどれでも）に、食い違いのある商品の分をまとめて保存する。読み取りが終わった時点では保存しない（職員が表記を直す前の読み違いを、記録に残さないため）。確定のあとに読み直した・直した商品は、次の確定のときに保存する
- 取り込みの一覧では、食い違いのある商品に「チラシの表記が、パッケージでの確認と食い違っています（○○）」と示し、確定したら記録を足したことを知らせる
- 外した掲載品（職員が外したもの・Claude が食品以外としたもの）も、一致した商品があり食い違いがあれば、同じ確定のときに記録を足す。外した理由は問わない（今週使わない商品でも、ほかの週の写しや献立に残りうるため。確認する側に倒す）。外した掲載品の一覧にも食い違いを示す。読み違いなら「戻す」で表記を直してから外す（2026-11-07 決定）
- 03 の 3 の「チラシを取り込んだときに参考の記録を追加するか」の表（記録がない → 追加 / 確認済みがある → 追加しない（食い違いはこの 3.5）/ 参考だけ → 品目が増えたときだけ追加）は変えない

### 3.6 使えない商品の表記を直す

- 職員はチラシと見比べて、アレルゲン表記の品目を直せる（減らすこともできる。SR-19 と同じく、品目を減らせるのは職員の操作だけ）。直したら分類し直す
- 直せるのは、**今回のチラシから読んだ品目**（3.4 の 1）だけ。説明文の探す言葉（2）・商品名の探す言葉（3）・マスタの記録（4）で当たったものは、取り込みの画面からは消せない（SR-14。マスタの記録はパッケージでの確認で直す）
- 読み取りの検証の「この品目の表記はない」という指摘で、品目を自動で消さない（SR-19）

### 3.7 外した掲載品

| ID | 要件 |
| --- | --- |
| FR-IMPORT-20 | Claude は読み取りのときに、**食品以外**の掲載品（洗剤・日用品・おもちゃなど）にも、ほかの商品と同じ項目を読んだうえで「食品以外」の印と理由を付けて返す（「戻す」で戻せるように）。アプリはその商品を外す。外した掲載品は分類せず、一覧の下の「外した掲載品」に商品名と理由を並べる（黙って消さない） |
| FR-IMPORT-21 | 職員は、どの分類の商品でも「外す」で外した掲載品に移せる（食品だがおやつに使わないもの・誤って読んだものなど）。外した掲載品は「戻す」で一覧に戻せ、戻すと分類し直す |
| FR-IMPORT-22 | 外した掲載品は今週の商品に入れず、商品の値（価格・内容量・入数など）も変えない。ただし 3.5 の食い違いの「参考」の記録だけは足す（記録は確認を増やす方向だけ） |

- Claude が外すのは食品以外だけにする。大袋のお菓子（入数が分からない）・乳幼児向けの商品・飲み物は外さない（入数は 3.3、乳幼児向けは職員が外す）
- おやつの分類（FR-FLYER-03e）の「対象外」は今までどおり商品の項目として残す（外した掲載品とは別）

## 4. アレルギー表記の略記の補正

コープのチラシは、アレルゲン表記を略して書く。アプリ（Biz）は、略記を元の品目に**戻して**（補正して）から判定に使う。

| 略記 | 品目 |
| --- | --- |
| 麦 | 小麦 |
| え | えび |
| か | かに |
| く | くるみ |
| そ | そば |
| 落 | 落花生（ピーナッツ） |
| カ | カシューナッツ（**追加**） |

| ID | 要件 |

### 5.1 分類ごとの確定

| 分類 | 1件ずつ | まとめて | 確定でアプリがすること |
| --- | --- | --- | --- |
| 🔴 使えない | 確定しない（今週の商品に入らない） | — | 何もしない。3.5 の食い違いの「参考」の記録だけは足す |
| 🟠 再入力 | 確定できない。直すと分類し直す | — | — |

- どちらも、確定した商品を掲載品の写し（`menus.listed_products`）に足す（FR-FLYER-07・06c は変えない）。確定済みの商品は一覧に「確定済み」として残し、選び直せる
- 「使えない」「再入力」「外した掲載品」の商品は、掲載品の写しに入れない。一覧の上に「今週の商品に入らない N件（使えない a件・再入力 b件・まだ確定していない c件）」と示す（FR-FLYER-06b）

### 5.2 まとめて確定・まとめて登録に入れない商品

次の商品は、分類が「使える」「要確認」でも、まとめての確定・登録に入れず、1件ずつ確定する。

| 入れない商品 | 理由 |
| --- | --- |
| アレルゲン表記が「表記なし」で、表の上のまとめからチラシと見比べた印をまだ付けていない商品（FR-FLYER-04a・D-97） | 「なし」は読み落としの可能性があるため |
| 取り込みの画面で手入力した商品（D-73） | 説明文がなく、読み取りの検証も通っていないため |
| 入数を入れて「使えない」から戻した商品（FR-IMPORT-11） | 読み取りの検証を通っていないため |
| 読み取りの検証（FR-FLYER-03g）ができなかった取り込みの商品（全件） | 読み違いを探せていないため |
| 表で行を開いて、確定のフォームで直している途中の商品 | 直した内容を捨てて、読み取ったままで確定しないため |
| 「要確認」で、おやつの分類・入数の候補がそろわない商品 | 新しく登録する項目が足りないため |

- **再入力で直したあとに「使える」「要確認」になった商品は、まとめて確定・登録に入れる**（上の表に当たらなければ）
- まとめての対象はサーバーが決めて返す。確定の API でもサーバーが分類と上の条件を確かめ直し、外れた商品は確定せず、確定した件数と確定しなかった件数を返す
- 「新しい商品をまとめて登録」は、今の D-98 のダイアログ（対象の商品名・税込価格・内容量・入数・おやつの分類・表記の原文と品目を全件並べ、既定ですべてに印、チラシと違うものは印を外す）を使う。「使える商品をまとめて確定」は、対象の商品名・一致した商品・税込価格・注文番号を並べる確かめのダイアログを出してから確定する
- 確定できない（エラーで返す）ときは、商品の追加・書き換え・記録の追加をしない（まとめての確定の途中で、ほかの商品の保存に混ざらない。03 の 5 のテストから変えない）

### 5.3 「再入力」での直し方

- 確定のフォームは、再入力の理由に当たる欄だけを開いて出し、理由（「税込価格が読めませんでした」「税抜298円と合いません」「マスタは12個、チラシは10個です」など）をその欄のそばに出す。ほかの欄は1行の要約にまとめ、「ほかの項目も直す」で開く
- 読み取りの検証の指摘は、直すか「このままでよい」を押すと消える（指摘ごと）。「このままでよい」は取り込みのメモリにだけ持ち、記録には使わない
- 商品名・メーカーを直したら照合し直す（一致する商品が変わることがある）
- 品目の分からない語は、品目を選ぶか「対応する品目なし」を選ぶ
- 直したらサーバーが分類し直して返す。結果が「使えない」になることもある（直した表記に避ける品目があったなど）

## 10. テストで必ず確かめること（xUnit）

**照合**

- 正規化した商品名とメーカーが両方同じときだけ一致する。商品名が同じでメーカーが違えば一致しない
- 全角・半角、カタカナ・ひらがな、「CO・OP」「コープ」、記号・空白の違いでは一致する（メーカーにも同じ正規化がかかる）
- 内容量が違っても一致する（そのうえで再入力になる）
- メーカーが空のチラシの商品は照合せず再入力になる。メーカーが空のマスタの商品とは一致しない
- 一致が2件以上のとき、最後に載った週が新しい方、同じなら更新日時が新しい方を使う
- 同じ商品を2回読んだら1件にまとめ、アレルゲンの品目は和集合になる。価格が食い違えば再入力になる

**分類**

- 入数の候補がなく、一致した商品にも入数がない → 使えない。一致した商品に入数があれば使えないにならない
- 入数を入れると分類し直され、まとめて確定に入らない
- チラシの表記・説明文の探す言葉・商品名の探す言葉・一致した商品の記録のどれか1つで避ける品目に当たれば使えない（それぞれ1件ずつ）
- 一致した商品が「使わない」なら使えない
- 使えない ＞ 再入力 ＞ 要確認 ＞ 使える の順になる（例：税込が読めず避ける品目を含む → 使えない。税込が読めず一致がない → 再入力）
- 税込が読めない・税抜と合わない・内容量・注文番号・商品名・メーカーが空 → 再入力
- 一致した商品と内容量か入数の候補が違う → 再入力。「このままでよい」で使えるになる
- 品目の分からない語がある → 再入力。品目を選ぶと分類し直す
- 読み取りの検証の指摘がある → 再入力
- 表記なしと読んだのに、一致した商品の有効な記録で特定原材料を含む → 再入力
- 一致した商品の記録が「参考」「要再確認」でも、避ける品目がなければ「使える」になる（アレルゲンの判定は 🟡 のまま変わらない）
- 一致した商品に記録がない（不明）とき、チラシの品目に避ける品目がなければ使える、あれば使えない
- 避ける品目が1つもないとき、避ける品目による使えないは起きない

**略記**

- 「麦」「え」「か」「く」「そ」「落」「カ」が、小麦・えび・かに・くるみ・そば・落花生・カシューナッツに当たる
- ひらがなの「か」はかに、カタカナの「カ」と半角の「ｶ」はカシューナッツに当たる。「か」がカシューナッツに、「カ」がかにに当たらない
- 「エ」「ソ」「ク」（カタカナ）は当たらず、品目の分からない語になる
- 「くっきー」「えびせん」「カカオ」は略記で当たらない（語全体の一致だけ）
- Claude が品目を返さなくても、表記の「カ」からカシューナッツが足される。Claude が返した品目は消えない

**確認済みとの食い違い（3.5）**

- 確認済みの商品で、チラシに避ける品目が増えたら使えないになり、最初の確定で「参考」の記録が足され、判定が「含む」（エラー）になる
- 避ける品目でない品目が増えたら使えるのまま、最初の確定で「参考」の記録が足され、判定が 🟡 になる
- 確定する前に職員が表記を直して食い違いがなくなれば、記録は足されない
- 外した掲載品も、食い違いがあればほかの商品の確定で記録が足される（今週の商品には入らない）。表記を直してから外せば足されない
- 確認済みの商品で、チラシの品目が確認済みの「含む」の中に収まっていれば、記録は足されない（今と同じ）

**確定**

- 使えない・再入力・外した掲載品は、確定の API でも確定できない（画面を通さずに送っても）
- まとめて確定・まとめて登録に、表記なしの見比べ前・手入力・入数を入れ直した・検証ができなかった・分類や入数の候補がない商品が入らない。確定の API で条件を確かめ直し、外れた商品は確定しない
- 再入力で直して使える・要確認になった商品は、まとめに入る
- まとめて登録した商品の記録は、どの品目も「含まない」にしない。表記なしは品目が空の「参考」になり、「安全」にならない
- 使えるの確定で、一致した商品の価格・注文番号は上書きされ、おやつの分類・タグは上書きされない。過去の週の取り込みでは上書きされない
- 確定がエラーになったときは、商品の追加・書き換え・記録の追加をしない

## 11. E2E（Playwright）で確かめること

- ダミーのチラシ（`samples/flyers/`）を取り込むと、4つの分類のタブに件数が出て、再入力 → 要確認 → 使える → 使えない → 確定済みの順に並ぶ
- 「使える商品をまとめて確定」「新しい商品をまとめて登録」で確定でき、今週の商品に入る。使えない・再入力の商品は今週の商品に入らない
- 再入力の商品の税込価格を入れると、分類が変わる
- 略記の表記（「（乳・麦）」「（カ）」）の商品が、補正した品目で表示される
- 「外す」「戻す」で外した掲載品との間を行き来できる

ダミーのチラシには、各分類に当たる商品（入数が分からない大袋、税込が読めない商品、メーカーのない商品、「カ」の表記の商品、一致するが内容量の違う商品など）を入れる（`samples/flyers/*.json` を直して `tools/build-samples/build.py` で作り直す）。
