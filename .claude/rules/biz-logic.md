# 計算・判定ロジックの決まり（Biz）

金額・予算・アレルゲン・重複・商品照合のロジックは Biz に置き、xUnit でテストする。Claude の出力は信用せず、ここで計算し直す。
このファイルには間違えやすい点だけを書く。定義の正は要件定義なので、書く前に参照先を読む。

## 金額（[02 §5「金額計算の定義」](../../docs/requirements/02-functional.md)）

- パック数（`menu_items.pack_count`）は保存する値（D-43）。既定は式で求める：**切り上げ**（その日の人数 × 1人あたりの個数 ÷ 入数）。1人あたりの個数は既定1
  - 入れ替え案と職員は、パック数を上書きできる
  - 献立づくりのエージェントは「何人分買うか」（servings）だけを返せる。パック数は同じ式（何人分 × 1人あたりの個数 ÷ 入数 を切り上げ）でアプリが求めて上書きする。その日の人数は変えない。使えない指定はエラー（`InvalidServing`）にするが、商品は外さない（FR-MENU-08b。D-102）
  - その日の人数か1人あたりの個数を変えたら、式で求め直す
  - パック数 × 入数 が その日の人数 × 1人あたりの個数 に足りなければ、警告を出す（禁止はしない）
- 入数・1人あたりの個数は1以上の整数、税込価格は1以上の整数。入数0は計算の前に拒む
- 1人あたり金額は小数のまま計算し、**表示するときだけ**円未満を四捨五入する
- 献立の商品の金額は、献立に入れた時点の価格（`menu_items.unit_price`）で計算する。商品の最新の価格は使わない
- おやつなしの日に商品があっても、その日の金額は0のままにする。「金額に含まれていません」の警告で知らせる（D-77）

## 予算（[02 §1「週の予算の扱い」](../../docs/requirements/02-functional.md)）

- 予算は週ごと。献立を作るときに既定の週の予算（`settings.default_weekly_budget`）を `menus.weekly_budget` に写し、職員が上書きできる。月の予算・月の実績は持たない
- 予算を超えても禁止しない。警告を出すだけにする

## 予算に合わせる入れ替え案（[02 §5.4](../../docs/requirements/02-functional.md)）

- 入れ替え案を出すのは、週の実績が週の予算に届かないときだけ（D-67）
- 探索はアプリ側で全通り試す。Claude に計算させない
- 目標額はその献立の週の予算（FR-MENU-27）。これを**超えない**範囲で、差が最も小さいものから上位3件。今の差より小さくならない案は出さない
- 試すのは「1か所の商品の入れ替え」「1日に1品の追加」「1か所のパック数 ±1」だけ（2か所以上の組み合わせは作らない）。同じ日にすでにある商品の追加は試さない
- 試すのは、日の種類が通常の日で、人数が1以上の日だけ（おやつなし・人数0の日は金額が0なので試さない。D-80）
- 候補から外すもの：03 §5 の判定が「入れられない」の商品（含む・含む可能性あり・不明）、税込価格か入数が未入力の商品、「対象外」の分類、「今週は使わない」にした商品、「使わない」商品。「参考」「要再確認」などの警告の商品は、警告の印を付けて候補にしてよい
- 候補は、その献立の掲載品の写し（`menus.listed_products`）から選ぶ

## 重複ルール（FR-COND-05、FR-MENU-12）

- 分類ごとの日数は `duplicate_avoid_days`（`{ 分類, 日数 }` の配列）で持つ。配列にない分類は制限なし
- 期間内の商品が入っても禁止しない。「○日前に出した」と警告する
- 比べるのは確定献立だけ。その日の日付から数え、同じ週の中の重複も警告する。Claude に渡す確定献立は、最も長い期間＋1週分（D-48）

## 献立案の検証（FR-MENU-15、[02 §5「確定」](../../docs/requirements/02-functional.md)）

Claude の案・手動の編集・チャット・入れ替え案のどれにも同じ検証をかける。

| 種類 | 内容 | 扱い |
| --- | --- | --- |
| エラー | 判定が「入れられない」の商品 / その週の掲載品にない商品 / 写しの税込価格か入数がない商品 / 存在しない商品 / 候補から外した商品（「今週は使わない」「使わない」「対象外」の分類。D-52） | Claude の案なら差し戻して直させる |
| 警告 | 判定が「警告」の商品 / 重複 / 予算超過 / 通常の日が0品 / おやつなしの日に商品がある / 全員分に足りないパック数 | 表示だけ。確定は止めない（D-75・D-77） |

- 確定を止めるのは、入れられない商品・価格か入数がない商品・掲載品にない商品の3つだけ（D-78）。候補から外した商品は、確定では警告にする
- 警告の商品は、確定時に商品ごとの確認が要る（SR-04・SR-22）

## アレルゲンの判定（[03 §5](../../docs/requirements/03-allergen-safety.md)）

- 「含む」品目と原材料の全文は、最新の記録1件ではなく「有効な記録」（最新の確認済みと、それより後のすべての記録）から求める。参考の記録で「含む」が減らないようにする
- 探す言葉・商品名・全文は同じ正規化（NFKC → カタカナをひらがなに → 空白・改行・記号の除去）をしてから部分一致で探す。商品照合用の正規化（「コープ」の除去あり）や `normalized_name` は使わない
- 探す言葉の正規化は、正規化したあとの位置を元の文字列の範囲に戻す対応も返す（当たった言葉を全文の上で強調するため）。改行・全角・カタカナをまたいで当たった場合も、元の範囲に戻せるようにする
- 判定の順序は 03 §5 の疑似コードどおりにする。**ステータスより先に「含む」「含む可能性あり」を調べる**。結果は「入れられない（エラー）/ 警告 / 安全」の3つに分け、どの条件にも当たらないときだけ「安全」にする
- 「要再確認」は保存しない。最新の「確認済み」の記録の確認日から、表示のたびに求める。`今日 - 確認日 > 再確認期間` で要再確認（90日なら、90日目までは期限内、91日目から要再確認）
- 判定に使う「今日」は引数か `TimeProvider` で受け取る（境界をテストできるように。`DateTime.Now` を直接使わない）
- 避ける品目の「探す言葉」は、商品名と原材料の全文（`raw_ingredients_ocr`・`raw_ingredients` の両方）を正規化してから探す（全角・半角、カタカナ・ひらがなの違いで見落とさない）。ステータスや職員の確定にかかわらず、見つかったら「含む可能性あり」（入れられない）にする（SR-14）
- 「確認済み」の記録がある商品には、チラシから「参考」の記録を追加しない。チラシの表記との食い違いは SR-20（D-100 で見直した 09 §3.5）のとおり扱う
- 避ける品目に「表示が確実でない」品目（推奨20品目・経過措置中のカシューナッツ。マスタの印で判断し、コードに品目を直書きしない）の印はマスタに残すが、画面には「メーカーへの確認が必要」を出さない（D-93。SR-06 は取り下げ）

## 商品名の正規化と照合（[09 §2](../../docs/requirements/09-flyer-import.md)。D-100 で D-63 の手順を置き換えた）

- 照合は、**正規化した商品名と正規化したメーカーの両方が一致したときだけ**同じ商品とする（FR-IMPORT-01）。内容量・税込価格・注文番号は照合に使わない（FR-IMPORT-02）。Claude は照合に使わない（Haiku の判定・Dice 係数の候補・似ている商品・職員が検索して紐づける操作は作らない。FR-IMPORT-05）
- 商品名の正規化は、保存するときと検索するときで**同じ関数**を使う：NFKC → カタカナをひらがなに → 「CO・OP」「コープ」の除去 → 記号・空白の除去（`ProductMatcher.NormalizeName`）
- メーカーは「コープ」を**除かない**正規化にする：NFKC → カタカナをひらがなに → 記号・空白の除去（`ProductMatcher.NormalizeMaker`。メーカーが「コープ」だけの商品が空にならないように）
- マスタの商品名・メーカーは、照合のたびに正規化し直して比べる（保存済みの `normalized_name` に頼らない。`normalized_maker` の列は作らない）。数百件なので全件でよい。形態素解析・ベクトル検索は使わない
- 商品名かメーカーが正規化で空なら照合しない（読み取った商品は「再入力」。マスタでメーカーが空の商品は、どのチラシの商品とも一致しない。FR-IMPORT-03）
- 一致が2件以上なら、最後に載った週（`listed_week_start`。値がある方 → 新しい方）→ 更新日時の新しい方 → ID の順で1件を使い、ほかの件数を返す（FR-IMPORT-04）
- 「使わない」の商品も照合する（一致したうえで分類が「使えない」になる）
- 内容量が違っても、名前＋メーカーが同じなら同じ商品で、**アレルゲン確認を引き継ぐ**（SR-05 の見直し）。マスタと内容量（正規化して比べる）か入数が違えば、再入力にせず「注意」（「内容量が変わりました。届いたらパッケージの原材料も見てください」）を出し、取り込みを終えるとチラシの値で上書きする。過去の週の取り込みでは上書きせず、空のときだけ埋める（FR-IMPORT-12。D-101）。名前＋メーカーが違えば別の商品で、引き継がない
- 内容量は正規化してから比べる：NFKC → 空白の除去 → 「×」「x」「＊」と括弧の書き方をそろえる（「40g（2袋×12個包装）」と「40g(2袋x12個包装)」を同じにする）
- 同じチラシの中の二重は、照合と同じ鍵（名前＋メーカー）で見つけて自動で1件にまとめる。アレルゲンの品目・探す言葉の当たり・品目の分からない語は和集合（確認する側に倒す）。税込・税抜・内容量・注文番号が食い違えば、先に読んだ値を使い「注意」を出す（再入力にしない。D-101）。名前かメーカーが空の行はまとめない（FR-IMPORT-06）
- 読み取りでまとめなかった行（手入力の行・名前やメーカーを直した行）も、取り込みを終えるときに同じ鍵で1件の商品にまとめる（同じ商品を2件登録しない）。後の行は先の行の商品を使い、商品の値は上書きせず、チラシの品目は「参考」の記録で足す（和集合）。同じ商品の、今週の商品に入れなかった行（使えない・再入力）のチラシの品目も、今週の商品に入るその商品の「参考」の記録に足す（09 §5.1）

## チラシ取り込みの分類（[09 §3・§5](../../docs/requirements/09-flyer-import.md)）

- 分類（使えない / 再入力 / 取り込める）は Biz（`FlyerItemClassifier`）が決め、画面は表示だけにする。「取り込みを終える」の API でも分類を求め直し、**使えない・再入力・外した掲載品は決して取り込まない**（D-101。要確認と使えるの区別、まとめての確定から外す例外（旧 09 §5.2）はない）
- 順番は **使えない ＞ 再入力 ＞ 取り込める**。理由は当てはまったものをすべて返す。再入力にしないもの（内容量・入数の違い・読み取りの検証の指摘・二重の読み取りの食い違い・税込と税抜が合わない・内容量や注文番号が読めない・入数の候補が内容量の表記と合わない・手入力）は「注意」として行に出すだけにする（09 §3.8）
- 「取り込める」なのに取り込みを終えるときに失敗する条件を作らない。登録できない値（1未満の税抜・空のタグ・選べる語にない味のタグ）は、読み取りの時点で読めなかった扱いにして除く
- 避ける品目による「使えない」は、チラシの表記（略記の補正後）・説明文の探す言葉・商品名の探す言葉・一致した商品の判定（03 §5 の含む / 含む可能性あり）のどれか1つで決まる。Claude の出力で外せない（外せるのは、職員が今回のチラシの表記の品目を直したときだけ）
- 取り込みの分類の「取り込める」は、アレルゲンの3つの表示とは別のもの。新しい商品や、一致した商品の記録が「参考」「要再確認」でも「取り込める」になるが、献立では今までどおり 🟡 として扱う（判定を変えない。記録がない（不明）ときは、取り込みを終えるときにチラシの品目の「参考」の記録を足してから使う。表記なしは品目が空の「参考（表記なし）」で、どの品目も「含まない」にしない）
- 略記の照合は、カタカナ→ひらがなの変換をかけない（`TextNormalizer.ForLabelAbbreviation`。「か」＝かに、「カ」「ｶ」＝カシューナッツ）。語全体の一致だけで当て、品目を足すためだけに使う（09 §4）
- 確認済みの商品とチラシの表記の食い違いは、避ける品目でなくても自動で「参考」の記録を足す。保存は「取り込みを終える」ときに、使えない・再入力・外した掲載品の分も含めてまとめて行う（09 §3.5）
- 取り込みを取り消したら（行を外す・取り込み済みの行を直す）、登録済みの商品に上書きした値（価格・税抜・注文番号・最後に載った週・内容量・入数）のうち、まだ上書きした値のままの項目を前の値に戻す。この取り込みで登録した商品は「使わない」にする（その商品で取り込んだ行がほかにないときだけ）

## テスト（Biz.Tests）

- 03 §5「テストで必ず確かめること」の項目は、すべてテストにする（ヘーゼルナッツの事例、90日・91日の境界、最新の記録が「参考」なら古い「確認済み」より優先される、など）
- 金額の切り上げ・切り捨てには、境界のテストを書く
- テストデータはダミーだけを使う（架空の商品名）。人数は現場の規模（40〜70人）に合わせる
