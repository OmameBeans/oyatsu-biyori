# 01. 概要

## 1. 目的

学童保育の職員が毎週1〜2時間かけているおやつ献立づくりを短縮する。

コープのチラシを撮影（またはファイルで取り込み）するだけで、1週間分の献立案を Claude が理由つきで提案し、職員はチャットで修正を依頼できる。アレルゲンの最終確認は、必ず職員がパッケージの原材料表示を見て行う。

献立の条件は2種類に分ける。

| 種類 | 内容 | 設定のしかた |
| --- | --- | --- |
| 固定条件 | **アレルギー・予算（週ごと）・人数** | 条件設定の画面で事前に登録する。アプリが必ずチェックする |
| 自然言語の条件 | その週ごとの要望（例：「しょっぱいものとゼリー系を合わせて出したい」「金曜は誕生日会なので豪華にしたい」「水曜は都民の日なので子どもが○○人」） | 献立を作るときに、文章で伝える |

## 2. 背景と課題

| 課題 | 内容 |
| --- | --- |
| 時間がかかる | チラシを見ながら献立を考える作業に、毎週1〜2時間かかっている |
| 条件が多い | アレルギー・予算・人数に加え、行事や組み合わせなど週ごとの事情を同時に考える必要がある |
| 気が抜けない | 子どもの安全に直結する作業を、保育の合間に行っている |
| 情報が足りない | チラシにはアレルゲン情報がほとんど載っていない |

## 3. 利用者

| 利用者 | 説明 | 主な端末 |
| --- | --- | --- |
| 職員（1人） | 献立を作る・商品のアレルゲンを確認する・施設の条件を設定する。開発者ではない | スマホ（撮影）、PC（ファイルの取り込み・献立の確認・編集） |

- **使うのは職員1人**を想定する（アカウントは1つ。職員の追加・権限の管理はしない）
- 想定する施設は1つ（複数施設への対応はスコープ外）
- ITに詳しくない人が、説明なしで使えることを目指す

## 4. 業務の流れ（このアプリを使った場合）

```
[事前準備] 固定条件の設定（人数・既定の週の予算・避ける品目）
     │
     ▼
① チラシを撮影 / ファイルで取り込み ─→ ② 商品を抽出 ─→ ③ 既存商品と照合・新規登録（職員が確定）
                                              │
                                              ▼
④ その週の要望を文章で伝える（行事・人数の変更・組み合わせなど）
     │
     ▼
⑤ Claude が要望をどう理解したかを示し、1週間分の献立案を理由つきで提案 ←─┐
     │                                        │
     ▼                                                                     │
⑥ 職員がチャットで修正を依頼 ────────────────────────────────────────────┘
     │
     ▼
⑦ 「参考」「不明」の商品があれば警告 → パッケージを撮影してアレルゲンを確認
     │
     ▼
⑧ 献立を確定・保存（次回以降の献立の参考に使う）
```

### 必須の中で作る順番

締切まで日がないため、必須の機能は、デモの山場（[08 の 2.2](08-hackathon.md)）に要るものから作る。

1. アレルゲンの判定・金額・正規化と照合のロジック（Biz と xUnit）。マスタの初期データ（29品目・追加品目・グループ）
2. ログイン・条件設定・避ける品目（献立を作る前提）
3. チラシ取り込み（読み取り → 照合 → 確定）。読み取りの検証（FR-FLYER-03f・03g）を含む
4. 献立作成（今週の商品 → 要望 → 献立案 → 検証と差し戻し → チャット → 確定）・献立一覧
5. アレルゲン確認（パッケージ撮影 → 確定 → 届いた後の警告）。ヘーゼルナッツの場面
6. 予算に合わせる入れ替え案・商品一覧と編集
7. ランディングページ・ダミーデータ・デモ動画・README

- PDF のページ選び（FR-FLYER-01a）と、届いた後の影響する献立の一覧（FR-MENU-37）は、簡単な形でよい
- 「余裕があれば」の機能（カレンダー）は、7 まで終わってから手を付ける。献立づくりのエージェントは必須にし、4 の中で最初からこの形で作る（D-82）

### 対象としない

- 商品の発注・コープへの注文連携
- 栄養価の計算・栄養指導
- 手作りおやつのレシピ管理（「手作りの日」として枠を確保するだけ）
- 保護者への配布物の作成
- 複数施設・複数団体での利用
- 他社の商品データベースからの一括取り込み（スクレイピングはしない）

## 6. 制約

- 締切：**2026-11-08（日）20:00 JST**（ハッカソン「Built with Claude: Japan 2026」提出）
- 開発者1人・約1週間。優先度「必須」から作る
- リポジトリは公開する。実データ（子どもの情報・実際の商品データ・画像）は入れない
- 技術スタックは [CLAUDE.md](../../CLAUDE.md) の通り（React + ASP.NET Core + SQLite + Claude API）

## 7. 成功の基準

| 観点 | 基準 |
| --- | --- |
| 時間 | 献立づくりが毎週1〜2時間 → 30分以内になる（目標）。締切までに現場の職員に試してもらい、実際にかかった時間を測る（[08](08-hackathon.md)） |
| 安全 | アレルゲンが「確認済み」でない商品が、警告なしに確定献立に入らない |
| 柔軟さ | 行事や人数の変更などの週ごとの事情を、文章で伝えるだけで献立に反映できる |
| 使いやすさ | 職員が説明なしで「チラシの取り込み → 献立確定」まで操作できる |
| デモ | 3分の動画で「撮る → 提案 → 修正 → 未確認の警告 → 確認済みにする」を見せられる。29品目外の食材（ヘーゼルナッツ）の見落としを防ぐ場面を入れる（[08](08-hackathon.md)） |
| 続けやすさ | 1週間あたりの API 費用を示せる（[NFR-COST-03](06-non-functional.md)） |

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| チラシ | コープの週ごとの商品案内。商品名・価格が載っている。JAN コードは載っていない |
| 商品 | おやつとして使う市販品。アプリの商品マスタに登録される |
| 献立 | ある週の、日ごとのおやつの組み合わせ |
| 固定条件 | アレルギー・予算（週ごと。既定の額を献立ごとに上書きできる）・人数。事前に設定し、アプリが必ずチェックする |
| 週の要望 | 献立を作るときに文章で伝える、その週だけの条件（行事・人数の変更・組み合わせなど） |
| 特定原材料（9品目） | 表示が義務づけられているアレルゲン（カシューナッツは経過措置中で、2028-03-31 までは表示がないことがある） |
| 特定原材料に準ずるもの（20品目） | 表示が推奨されているアレルゲン。表示されないことがある |
| 29品目 | 特定原材料9品目と準ずるもの20品目の合計（2026年4月の改正で28品目から変更） |
| 表示が確実でない品目 | 表示されないことがある品目（推奨20品目と、経過措置中のカシューナッツ）。「表示なし」を「含まない」とみなさない |
| アレルゲン確認 | 商品にどのアレルゲンが含まれるかを記録すること。履歴として積み上げる |
| 確認済み / 参考 / 不明 | アレルゲン情報の確からしさ。詳細は [03](03-allergen-safety.md) |
| 要再確認 | 「確認済み」でも、確認日から一定期間が過ぎた状態 |
| 正規化名 | 照合用に表記ゆれをそろえた商品名 |
