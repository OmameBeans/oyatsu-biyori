# screen-flow

画面遷移図を作る。stack-diagram（技術構成図のスキル）の見た目と作り方を、画面の図に置き換えたもの。**1つの自己完結した HTML が正本**で、PNG や Artifact はそこから作る。

- 画面 ＝ 160×100 の PC の枠（タイトルバーつき）か 56×100 のスマホの枠。中身はサムネイル、なければ CSS のワイヤーフレーム
- 画面の下に、画面 ID（色つきの等幅）・画面名・URL
- グループの枠 ＝ 公開範囲（ログイン不要／ログイン後）、共通レイアウト（サイドバーのあるホームなど）、1画面の中のタブ・手順
- 矢印 ＝ 主な流れ（色つき）・遷移（灰色）・条件つき／自動（破線）・往復（両矢印）。● が入口

## 必要なもの

- Python 3.7 以上（標準ライブラリだけ）
- 撮影用のブラウザ：Playwright（Python）があればそれを、なければ手元の **Edge / Chrome をヘッドレスで** 使う（Windows なら Edge が最初から入っているので追加のインストール不要）。場所は環境変数 `SCREEN_FLOW_BROWSER` でも指定できる
- モックが Web フォント（Google Fonts など）を読むならネット接続

以下、`<skill>` はこのスキルのフォルダ（`.claude/skills/screen-flow`）、`<work>` は作業用のフォルダ（スクラッチパッドなど。リポジトリの外がよい）。

## 手順

1. 中身を決める（画面・グループ・遷移）
2. サムネイルを撮る（任意） — `scripts/shoot_screens.py`
3. 座標を決める — `references/geometry.md` を読む
4. テンプレートから HTML を作ってビルド — `scripts/build.py`
5. **PNG にして自分の目で見る**
6. 渡す

## 1. 中身を決める

情報源を探す順：要件定義の画面一覧・画面遷移の節 → ルーターの定義（React Router の routes、`pages/` / `app/` の構成など）→ モックの HTML。**書かれていない遷移を作らない**。根拠が見つからない遷移は図に入れず、ユーザーに「〇〇から△△へは戻れる想定ですか」と最後にまとめて聞く。

決めること：

- **画面**：画面 ID・画面名（全角12文字まで）・URL（なければ「ダイアログ」「タブ」「手順1」など）・端末（PC／スマホ優先なら sp）・状態（未着手や「余裕があれば」なら planned と札）・サムネイルの出どころ
- **グループ**
  - `area`：公開範囲。「ログイン不要」と「ログイン後」を分けるのが基本
  - `shell`：共通レイアウト（左サイドバーのあるホームなど）。**中の画面どうしのサイドバー移動は線を引かず、この枠で表す**（全部引くと線だらけになる）。凡例にもそう書く
  - `sub`：1つの画面の中のタブ・ウィザードの手順。タブはサムネイルを並べるだけで線を引かない。手順は手順1→2→3… を主な流れでつなぐ
  - 入れ子は2段まで（area か shell の中に sub）
- **遷移**（from・to・きっかけ・種類）
  - 主な流れ `e`：利用者がいちばん通る道を1本（入口 → ログイン → 目的の画面 …）
  - 遷移 `n`：ボタン・リンクでの移動
  - 条件つき・自動 `n dash`：未ログインでのリダイレクト、保存後に戻る、エラー時など
  - 往復 `marker-start` も付ける：ダイアログを開いて閉じる、表示切り替え
  - ラベルはボタン名・きっかけを短く（「献立を作る」「未ログイン」）

迷ったら、図に描く前に「画面 × 遷移」の表をユーザーに見せて確かめてもよい。テンプレートの遷移一覧（`table.tx`）にそのまま入れられる。

## 2. サムネイルを撮る（任意）

```bash
python <skill>/scripts/shoot_screens.py <work>/shots \
  menus=mocks/menus.html check=mocks/allergen-check.html@sp list=http://localhost:5173/menus
```

- `名前=パスまたはURL` が PC（1280×800 で撮り、frame 160×100 に入る）、末尾に `@sp` でスマホ（390×696）
- `<work>/shots/<名前>.png` ができ、HTML では `%%ICON_<名前>%%` で参照する
- `--scale 0.5`（既定）で1枚 50KB 前後。画面が20枚を超えるなら `--scale 0.25`
- 撮れるのは「開いた直後の見た目」だけ。タブの2枚目・ダイアログ・手順の途中などは、モックが URL（`?tab=`・`#step2` など）で開けるならそれを使い、無理ならワイヤーフレーム（`wf`）にする。撮れたサムネイルとワイヤーフレームが混ざってかまわない
- 撮ったら1〜2枚 Read で見て、読み込み中・エラー画面になっていないか確かめる（遅いなら `--wait 8000`）
- **実データが映る画面は撮らない**。モックやダミーデータの環境だけ。本番の画面のスクリーンショットを図に入れない

## 3. 座標を決める

`references/geometry.md` を読む。要点：画面は frame と下の文字をあわせた 176×144 の箱。横の線は frame の中段どうし、縦の線は「上の箱の下端 → 下の frame 上端」。文字を横切る線は引かない。

並べ方の目安：

- 左 → 右 ＝ 利用者が進む順（ランディング → ログイン → ログイン後）。主な流れを1行にまっすぐ通す
- 上 → 下 ＝ サイドバーの項目の順（1行目＝最初に出る画面、その下に他の項目）
- 2つ以上の画面から来る画面（例：アレルゲン確認）は、来る元たちの間の下の行に置き、折れ線で集める
- 横に長くなるのはかまわない（スクロールできる）。縦横とも詰めすぎない

## 4. ビルド

`<skill>/assets/template.html` を `<work>/flow.html` にコピーし、GROUPS / EDGES / SCREENS / ヘッダー・凡例・遷移一覧・フッターを書き換える（テンプレートの書き方がそのまま書式の説明になっている）。

- キャンバスの大きさは **3か所**（`.canvas` の width/height、`svg.edges` の width/height、`viewBox`）をそろえる
- `<html lang>` はラベルの言語に（日本語なら `ja`）
- 色やフォントは `:root` のトークンだけを変える
- サムネイルのない画面は `frame pc wf`（サイドバーつきの画面は `wf side`）、ダイアログは `frame pc modal wf`、スマホは `frame sp wf`

```bash
python <skill>/scripts/build.py <work>/flow.html <work>/shots <work>/out.html --fonts <skill>/assets/fonts
```

サムネイルがなければ、空のフォルダを ICONDIR に渡す。`%%…%%` が残ると止まる（ファイル名の打ち間違いか `--fonts` 忘れ）。

## 5. PNG にして見る

```bash
python <skill>/scripts/render_png.py <work>/out.html <work>/out.png --scale 2
```

ライト（`out.png`）とダーク（`out-dark.png`）ができる。キャンバスだけが写る（見出し・凡例・表は入らない）。**両方を Read で見て**、次を確かめる：

- 線が画面名・URL を横切っていない。矢じりが文字や frame の中に刺さっていない
- 線のラベルが読める（紙色のふちどりが効いている）。グループの枠線がラベルを貫いていない
- グループのラベルが左上にあり、画面や線と重なっていない。左右の余白がそろっている
- 何もグループの枠からはみ出していない。キャンバスの端で切れていない
- サムネイルが読み込み中の画面になっていない。planned の札がダークでも読める
- 主な流れが1本につながって読める

直して撮り直す。これは安い。重なった図を渡すほうが高くつく。

## 6. 渡す

- **HTML**（既定）：ビルドした `out.html`。フォントもサムネイルも埋め込み済みで、オフラインで開ける
- **PNG**：`render_png.py` の出力。必ずビルドした HTML をブラウザで撮って作る（別の方法で描き直さない）
- **Artifact**：Artifact ツールがあれば、`out.html` をそのまま公開できる（外部の読み込みがないので動く）。会話で何度も直すときに向く
- 置き場所はユーザーに聞く。リポジトリに入れるなら、サムネイルがモック・ダミーデータだけであることを確かめてから

フッターの左に出典（例：`docs/requirements/05-screens.md・mocks/ から作成`）、右の「based on stack-diagram」はそのまま残す。
