# 画面の E2E（Playwright）

画面の要件を、要件 ID つきのテストで確かめます（D-87・T0-15）。

## 走らせ方

```
cd src/oyatsubiyori.client
npm run e2e
```

- サーバーは `ASPNETCORE_ENVIRONMENT=E2E` で起動します（`https://localhost:7175`）。DB（`oyatsu-biyori.e2e.db`）は毎回作り直し、TD-02 のダミーデータを入れます
- **Claude は偽物**です（`OyatsuBiyori.Server/E2E/FakeClaudeServices.cs`）。チラシの読み取りは `samples/flyers/flyer-02.expected.json`（設定の `E2E:FlyerSample`）を返します（画面から送る画像はブラウザで JPEG に描き直されるので、どのファイルを選んでもこのチラシの正解が返ります。画像ごとに正解を選び分けるのは、PNG をそのまま送る読み取り精度の測定の自己確認だけです）。費用がかからず、毎回同じ結果になります。Biz の検証・アレルゲンの判定は本物を通します
- 偽の読み取りの検証は、いつも1件目に「入数」の指摘を1つ返します（1件目は「再入力」になり、「このままでよい」で消えます）。商品の照合に Claude は使いません（D-100。名前＋メーカーの完全一致だけ）
- 偽の Claude とダミーデータは E2E の環境でだけ登録されます。本番（環境名・接続文字列・IIS）では `DemoDataGuard` が止めます
- 画面は Vite の開発サーバー（`https://localhost:60235`）から開きます
- 初めて走らせるときは、ブラウザを入れます：`npx playwright install chromium`

## プロジェクト

| 名前 | 中身 |
| --- | --- |
| setup | 最初に1回ログインして、状態を `e2e/.auth/state.json` に保存する |
| pc | 1280×800 |
| mobile | Chromium のスマホの幅（Pixel 7） |

同じ DB を使うため、1つずつ順に走らせます（`workers: 1`）。テストは、前のテスト（PC）で変わったデータでも通るように書きます。

## 決まり

- テストのファイルは画面ごと（`sc-09-menu-edit.spec.ts` など）
- テストの名前は要件 ID から始め、満たすべき条件を日本語で書く（`FR-MENU-14 🔴 の商品を入れると確定できない`）
- 要素は役割と文言で探す（`getByRole`・`getByText`）。CSS のクラスや DOM の構造に頼らない
- 画面ごとに PC とスマホの画像を1枚ずつ `e2e/screenshots/` に撮る（`captureScreen`。目で見る用で、ピクセルの比較はしない。iOS Safari は実機で確かめる）
- 使うデータは TD-02 のダミーデータだけ

## チラシ取り込みの分類（D-100）

`flyer-02` の20商品とダミーデータ（ナッツ類を避ける）で、取り込みの分類は次のようになります（PC で最初に取り込んだとき。[09. チラシ取り込みの分類](../../../docs/requirements/09-flyer-import.md)）。一覧は19件で、並びは 再入力 → 要確認 → 使える → 使えない → 確定済み です。

| 分類 | 商品（注文番号） | 理由 |
| --- | --- | --- |
| 再入力 | チーズ味 ひねりスティック（8107） | 読み取りの検証の指摘（偽の検証が1件目に返す） |
| 再入力 | CO・OP さくさくクッキー（8102） | 登録済みと名前＋メーカーが同じで、内容量が違う（10袋入 → 5袋入。FR-IMPORT-12） |
| 再入力 | コンソメ ポテトスティック（426）・どうぶつ型 ココアクッキー（424）・徳用 ミルクチョコ 小分けパック（421） | 入数の候補が内容量の表記と合わない |
| 再入力 | ふんわり 抹茶ロール（428） | 税込価格が読めない（税込375円を入れると要確認） |
| 再入力 | にこにこ ミニドーナツ（8121） | メーカーが読めない（FR-IMPORT-03） |
| 要確認 | ことりのさくさくショコラ（8104）ほか、一致する商品がない9件 | 新しい商品。表記なしの3件（のりしお・ピピ ラムネ・根菜チップス）は、チラシと見比べるまでまとめての登録に入らない |
| 使える | くまのポッケ ミルクビスケット（8103） | 登録済みと名前＋メーカー・内容量・入数が同じ |
| 使えない | うすしお ポテトチップス 大袋（8110） | 入数が分からない（入数を入れると分類し直す。FR-IMPORT-10・11） |
| 使えない | こつぶ しお豆スナック（427） | 表記「（乳・カ）」の「カ」＝カシューナッツ（FR-IMPORT-32） |
| 外した掲載品 | キッチン スポンジ 3個（429） | 食品以外（FR-IMPORT-20） |

- `flow-hazelnut.spec.ts`（PC だけ）がショコラを新しい商品として登録し、パッケージでヘーゼルナッツが見つかるので、`sc-09-menu-edit.spec.ts` ではショコラは「使えない」（登録済みの商品の記録）になります
- スマホのテストは PC のあとに同じ DB で走るので、PC で登録した商品は「使える」になります。テストは件数や分類を決め打ちせず、PC だけで確かめるところは `testInfo.project.name` で分けます
